# 从电话问安到“一键呼叫”：空巢、远距子女、照护半径与居家养老可执行性（中国，2007—2026）

## 研究问题

这篇不写一部完整的中国养老政策史，也不把“电话 → 呼叫器 → 摄像头 → 物联网传感器 → AI”写成技术越来越先进、老人因此越来越安全的直线进步史。

它问一个更接近日常生命历程的问题：

> **当成年子女因为工作、迁移、住房或自己的家庭而不能和父母同住时，一个老人继续住在自己家里，究竟需要哪些外部条件才能变成一种可执行的生活，而不是一句“居家养老”的抽象偏好？**

至少要把以下状态分开：

```text
老人独居 / 与配偶居住
≠
老人愿意继续住在原住房
≠
老人拥有可用电话/终端
≠
老人知道怎样求助
≠
紧急时能触及终端
≠
信号真正发送
≠
平台/联系人收到
≠
有人理解发生了什么
≠
有人愿意响应
≠
有人能在足够短时间内到场
≠
老人真正获得医疗、照料或生活帮助
≠
长期居家生活因此可持续
```

因此本文加入三个核心变量。

### `care radius / 照护半径`

照护不是“有/没有”的二元变量。成年子女、邻居、社区工作人员、助老员、家庭医生、120、家政人员都可能成为照护者，但他们离老人有不同的时间距离。

真正关键的问题是：

> **老人突然需要一个真实身体到场时，谁能在几分钟、几小时或一天内到达？**

### `summonability / 可呼叫照护性`

居家养老的一个基础条件，不只是“有人愿意帮”，而是老人能否在需要时把需求送到正确的人那里。

电话、热线、一键呼叫、可穿戴设备、传感器和平台都在改变这种 `summonability`。

### `ageing-in-place executability / 原居养老可执行性`

“我想继续住在自己家里”只是偏好。要把它维持成现实生活，还需要：

- 基本生活能自理或有人补足；
- 急病/跌倒等风险有求助路径；
- 日常采购、做饭、清洁、用药、就医有人执行；
- 子女不在时仍有本地 fallback；
- 技术设备老人会用、够得着、能供电、能联网；
- 监测与隐私之间能被本人接受。

这篇与仓库现有“远程育儿”专题形成代际镜像：儿童照护里，信息可以远程移动而身体劳动仍留在本地；老年照护同样如此。

## 一、先向 Web 以前退：远程照护不是 Internet 发明的

### 1. 1974—1976：电话线已经可以被设计成“独居者的远程安全接口”

美国 Andrew S. Dibner 的自动电话报警系统专利于 1974 年申请、1976 年授权。[S1]

专利的出发点非常明确：一些独居的老年或体弱者担心突然失去行动能力后无法求助，传统人工定期检查耗费时间且可能不可靠。

设计不是 Internet 系统，而是家庭固定电话 + 定时器 + 自动拨号：

```text
老人正常使用电话
→ 定时器被重置
→ 若长时间没有电话活动
→ 系统报警 / 自动拨预设号码
→ 播放预录求助信息
```

同时也保留手动紧急开关。

它说明：

> **“把一个独居者的异常状态传到远方”至少在 1970s 就已经是电话网络上的工程问题。**

Web、App 和 IoT 后来改变的是传感密度、后台可见性、联系人路由和服务调度，不是第一次创造“远程求助”。

### 2. 英国社区报警系统进一步说明：信号不能替代本地响应者

后来的学术研究回顾 Leeds telecare 时指出，当地服务最初就是社区报警系统，后在 2000s 扩展；到 2011 年，使用者会提供两名愿意在需要时到场的朋友或亲属，若附近联系人无法响应，市政响应中心才提供后备应急响应。[S2]

这个海外比较的重要性不在于“英国更早”，而在于它把一个跨国共同机制说得非常清楚：

```text
remote alert
≠
embodied care
```

报警系统真正做的是**压缩发现异常与启动本地照护之间的延迟**。

## 二、2007—2011：中国的“远程养老”首先是一套电话、社区与人工服务的混合系统

### 3. 2007—2008：96156 说明“远程照护”首先可以是热线，不必先是网站

北京 2007 年的“96156亲情服务卡”已经把政府购买的家务、陪同、代办、维修等服务连接到一条社区服务热线。[S3]

2008 年，96156 又增加面向空巢老人的“亲情倾听”和热线购药服务：老人可以申请定期问候或陪聊，由心理咨询师、志愿者和社区人员承担。[S4]

这形成一种早于智能手机的照护接口：

```text
老人/家属拨电话
→ 话务员理解需求
→ 信息被记录
→ 志愿者/社区/服务商被联系
→ 电话陪伴或现实服务
```

这里最重要的不是“有了热线老人就不孤独”，而是：**家庭之外出现了一个可以被主动呼叫的公共照护节点。**

### 4. 2008 同期个人材料：电话把儿子的声音带回来，但没有把儿子本人带回来

2008 年南京一项针对 400 户空巢老人的调查被新华社报道。报道同时采访了 72 岁的李秀珍：丈夫早逝，女儿也已去世，唯一的儿子在国外五年没有回国；她腿脚有病，外出越来越少，每次儿子来电话都会高兴好几天，但日常仍主要独自生活。[S5]

证据等级：**B：同期媒体调查 + 同期人物采访。**

这条材料非常适合建立：

### `contactability / care-presence gap / 可联系—照护在场缺口`

```text
能通电话
≠
有人在身边
≠
有人能扶起跌倒的身体
≠
有人能代替完成做饭、买药、送医
```

因此不能把通信进步直接写成“解决空巢”。

### 5. 2009：杭州“电子保姆 / 全球眼”把老人第一次做成可被后台观察的状态

杭州拱墅区的同期报道记载：2007 年起已为部分老人安装随身“电子保姆”呼叫器；到 2009 年，又给符合条件的高龄、困难、重残老人安装“全球眼”摄像头和带 GPS、一键通功能的 CDMA 手机，并把图像和求助接到社区居家养老中心及 96345 便民平台。[S6]

报道明确说摄像头安装是在征得老人同意后进行。

这里出现了两个不同机制：

- **active summon / 主动呼叫**：老人按按钮；
- **remote observation / 远程观察**：后台可以看到家庭内状态。

它们不能混成一个“智慧养老”按钮。

主动呼叫要求老人有意识、能触及设备、知道怎么用；被动/持续观察则减少了主动操作要求，却引入明显的隐私与监控边界。

### 6. 2009：同一养老事务已经同时存在电话、网站、短信、邮件

2009 年北京 96156 对外说明，养老院和居家养老信息可通过四种方式获取：

- 电话 96156；
- 网站 `www.bjcs.gov.cn`；
- 短信 `1069031596156`；
- 邮件 `bjcs@bjcs.gov.cn`。[S7]

这说明一个非常重要的 adoption 规律：

> **养老事务上网，不等于老人开始以 Web 为主要入口。**

对于高龄用户，电话完全可能仍是最可执行的前端；Web 更可能被成年子女、社区工作人员或服务人员使用。

### 7. 2010—2011：“虚拟养老院 / 一键通”把照护做成调度网络

兰州城关区 2009 年开始建设“虚拟养老院”。2010 年《光明日报》报道时，老人仍住在自己家里，通过服务网络和电话获得社区医院、送餐、上门服务等；一位魏姓老人直接评价社区医院和上门服务“方便、便宜”。[S8]

2011 年杭州上城区的“一键通”又把终端上的红、黄、绿按键分别连接到紧急救助、社区服务和生活服务。[S9]

这意味着“养老院”开始可以从**一个住进去的建筑物**，部分拆成：

```text
家庭住房
+ 呼叫终端
+ 话务/信息平台
+ 服务商目录
+ 社区工作人员
+ 医疗/急救
+ 上门照护
```

这不是把机构养老“虚拟化”这么简单，而是让一部分原本必须通过同住家属或入住机构才能获得的服务，开始可以按需进入家庭。

## 三、2015—2019：设备越来越多以后，真正的瓶颈开始暴露在“会不会用、够不够得着、谁来上门”

### 8. 2018 济南反例：`installed ≠ reachable ≠ remembered ≠ used`

2018 年《齐鲁晚报》调查济南智能养老设备时，回顾当地 2008 年已试运行“一键通”、2009 年正式运行，但报道重点恰恰是使用率问题。[S10]

72 岁的张永红 2012 年得到固定式一键通设备。2014 年她在厨房突发心脑血管疾病晕倒，幸好邻居在场打 120。她后来解释：设备在客厅电话机旁，自己人在厨房倒下，根本不可能再走过去按按钮。

另一名老人拿到腕表式设备后，因为字小、按键小、要装手机卡和充电，担心弄坏，最后也没有真正使用。

这形成四个硬边界：

```text
terminal installed
≠
terminal physically reachable
≠
user remembers it during emergency
≠
user can operate it
≠
request successfully leaves the home
```

这是对“智慧养老 = 设备覆盖率”的直接反证。

### 9. 同一报道的另一条路径：真正救人的可能是社区里那个身体

87 岁的李庆英感到头晕，因为子女住在外地，她自己走到社区综合养老服务中心。社区助老员测到异常后把她送医、办理住院并通知家属；子女到晚上八点多才赶到。[S10]

这里真正发挥作用的并不是一个更先进的传感器，而是：

```text
老人能到达社区节点
→ 社区人员识别严重程度
→ 本地人员身体行动
→ 医院接手
→ 远方子女随后到场
```

因此新增：

### `local-body fallback / 本地身体兜底`

远距家庭能成立，并不意味着家属劳动消失，而是需要某种本地行动者在“子女赶到以前”接住时间差。

### 10. 2019 上海：成功案例同样证明平台背后必须有人到场

2019 年上海黄浦区近百岁的张阿婆独自在家跌倒，按动口袋里的按钮后，报警传到街道“养老管家”工作室；养老管家和居委干部先上门，再联系家属送医。[S11]

同一系统还通过红外设备显示部分居家活动、睡眠状态。

这条成功链不能简写成“一键呼叫救了老人”，更准确的状态是：

```text
button accessible
→ alert transmitted
→ staffed desk receives
→ human interprets
→ local workers can enter/arrive
→ family is reachable
→ hospital route executable
```

按钮只是第一段。

### 11. 2019 西安：平台也可以把“需要服务”与“继续参与社会”放在同一人身上

82 岁的刘阿姨在莲湖区“虚拟养老院”同期采访中说，自己可以用电话一键叫来服务、接受定期健康检查，同时仍参与社区组织并为其他老人服务。[S12]

这条材料提醒我们：

> **老年人不能只被建模成被动的照护接收者。**

同一个人可以一边需要某些支持，一边仍是志愿者、邻里照护者、组织成员和信息提供者。

## 四、2020—2022：偶发型未来让“服务能不能在身体移动受限时继续”变成核心

### 12. 2020：疫情期间，虚拟养老院的关键仍是“远程发现需求 + 本地有人送过去”

2020 年西安莲湖区的同期报道里，82 岁独居的刘阿姨接到虚拟养老院工作人员电话，提出需要买菜，工作人员随后安排送菜。[S13]

兰州同期材料则记录助老服务员继续上门做饭、洗衣、清洁和陪伴。[S14]

这说明在日常流动受冲击时，平台的价值不是让所有照护“在线化”，而是维持：

```text
远程询问/呼叫
→ 需求可见
→ 本地服务人员仍能执行
```

因此加入：

### `care-continuity under mobility shock / 流动冲击下的照护连续性`

### 13. 2021：家庭养老床位把住房变成“半机构化”节点

广州 2021 年的同期报道里，89 岁独居老人林少珍的床边同时有紧急按键、红外人体探测器和智能感应床垫；子女可以在手机上查看部分健康与活动数据。[S15]

这形成一种新的家庭基础设施：

```text
private home
+ institutional sensors
+ care platform
+ remote family visibility
+ professional service
```

但必须保留：

### `telemetry / care gap / 遥测—照护缺口`

看到异常数据，并不等于已经完成照护。平台仍需决定谁响应、谁上门、谁承担费用、谁负责后续。

## 五、2023—2026：防守型未来里，安全缓冲开始包含“我不在父母身边时，还有谁知道出事了”

### 14. 2024：独居有时是老人自己的生活选择，而不是“子女不要老人”

武汉 2024 年同期报道中的江德玉已经 92 岁，有三子一女，但她坚持独自居住，不愿给子女添麻烦。女儿下班后每天绕去看她，子女白天还会多次打电话；老人耳背、常接不到电话，又增加了家庭焦虑。社区后来为她提供智能陪伴机、门铃和烟感等设备。[S16]

这条材料非常重要，因为它拒绝了两种简单叙事：

- “独居 = 被遗弃”；
- “有四个孩子 = 一定有人全天照护”。

这里更准确的是：

### `independence preference / family work-time conflict / 独立偏好—家庭工作时间冲突`

老人可能希望保留自己的住房与生活节奏；成年子女也可能愿意照护，但白天必须工作。技术和社区服务于是被用来填两个时间表之间的空档。

### 15. 2025：子女的“工作日安全缓冲”开始由多联系人和被动传感器构成

北京上地街道 2025 年为部分高龄、独居、空巢老人安装一键终端、SOS 按钮、红外传感器、门磁和网关。家属在同期采访中明确说，最大的焦虑是白天上班时老人身边没人；新系统可通过电话、短信、App 通知多个联系人。[S17]

这可以写成：

### `care buffer / 照护缓冲`

和现金缓冲类似，它不是保证风险不发生，而是让一个家庭在本人不能立刻到场时仍保留响应路线。

### 16. 2026：成熟系统越来越强调“分级响应”，而不是只强调按钮

天津河东区 2026 年的现场测试里，家属描述：按键后平台几秒内回拨老人；如果老人不能接听，平台再联系家属。官方说明则把家属、社区网格员和医疗救援纳入分级响应。[S18]

安徽凤阳同年一套系统会把求助同步发送给网格员、子女和结对邻居等多个关联联系人。[S19]

因此真正重要的技术变化之一不是按钮本身，而是：

### `response fan-out / 响应扇出`

```text
一个异常
→ 多个可能响应者
→ 至少一个本地身体接单
```

这降低了“唯一联系人没接电话”的单点失败风险。

## 六、四种未来时间感：养老线让模型进一步具体化

### 2005–2012：扩张型未来

这一时期不能简单写成“年轻人都相信未来越来越好”。在养老这一格，更具体的变化是：

- 成年子女可以迁往更远城市工作；
- 老人开始获得电话、热线、社区服务、一键呼叫等补充渠道；
- “孩子不与我同住”开始更可能与“我继续住在原社区”并存。

但本文不作因果跳跃：这些服务不证明它们**造成**了迁移，只证明分居家庭多了一些可执行的补丁。

### 2015–2019：拥堵型未来

家庭成员的工作时间、老人居住偏好和照护需求越来越需要被同时安排。

技术设备增长，但 2018 济南反例证明：

> **设备覆盖可以扩张，实际可用性仍然堵在老人会不会用、设备放在哪里、平台是否有人、附近有没有响应者。**

### 2020–2022：偶发型未来

当正常出行和上门节奏受到冲击，家庭开始更依赖电话、视频、后台监测和本地服务人员维持照护连续性。

关键不是“线上取代线下”，而是：

> **线上发现需求之后，线下还能不能继续有人执行。**

### 2023–2026：防守型未来

这一阶段的防守不只是存钱、考证或找稳定工作，也包括：

- 为父母家安装一个紧急呼叫入口；
- 给异常状态配置多名联系人；
- 用传感器降低“几小时没人知道”的风险；
- 在老人坚持独居时尽量保留这种生活选择；
- 让子女白天工作时不必持续处于“现在家里是不是出事了”的不确定状态。

这是一种 **`care-risk buffering / 照护风险缓冲`**。

## 七、海外比较：共同问题不是 Internet，而是“远方信号怎样变成本地身体”

美国 1974 年电话报警专利和英国后来长期使用的 community alarm / telecare 说明，远程照护的基本结构在 Web 以前已经成形：[S1]、[S2]

```text
person at home
→ telephone / pendant / alarm
→ remote receiver or monitoring centre
→ named relative / friend / local responder
→ physical attendance
```

中国 2007—2026 的 96156、一键通、虚拟养老院、全球眼、家庭养老床位和 IoT 平台改变了接口与规模，但没有消除最后一段。

因此跨国共同机制是：

> **通信基础设施可以把异常、请求和责任路由到远方，却不能把一个人的身体瞬移到老人家里。**

中国案例更突出的地方，是社区居委、网格员、政府购买服务、助老员、家政/养老企业和成年子女经常共同组成响应栈。

## 八、证据矩阵：它补进“人怎么活着”的哪些格子

| 维度 | 本轮新增理解 |
|---|---|
| 教育 | 非核心；数字素养和设备教学会影响老人能否独立使用服务 |
| 就业 | 成年子女工作时间与照护时间直接冲突 |
| 住房 | 原住房可以因外部服务栈而延长可居住期 |
| 婚姻家庭 | 与子女分居不再等于完全失去家庭照护，但家庭责任被重新分配 |
| 迁移 | 子女远距迁移后，父母仍可能留在原社区；需要响应网络补足距离 |
| 照护 | 从“同住者随时在场”扩展到多节点、可呼叫、分级响应照护 |
| 非正规劳动 | 邻里、志愿者、亲属等非职业照护仍是重要 fallback |
| 长期中断 | 配偶去世、疾病、行动能力下降会重写原有独居可执行性 |
| 证件与记录 | 服务平台开始保存地址、身体状况、联系人、告警与服务记录 |
| 通信方式 | 电话热线 → 呼叫器/CDMA → 摄像头 → 手机/App/IoT，多渠道长期叠加 |
| 互联网平台 | Web 往往不是老人唯一或主要前端，后台调度的重要性高于页面本身 |
| 信息获取 | 老人/家属可以查询服务，平台也可以获得老人状态 |
| 社交关系 | 远方子女、邻居、社区人员成为不同半径的照护关系 |
| 未来预期 | “以后还能不能住自己家”开始取决于外部支持栈而不只取决于有没有子女 |
| 线上/线下身份 | 平台中的“老人档案/联系人”不等于现实中能响应的真实照护者 |
| 平台消失与记忆保存 | 公共网站可能留下服务介绍，真实呼叫、误报、无人响应等 transaction state 更易消失 |

## 九、反例与后见之明风险

### 1. 不要把独居浪漫化成“自主养老”

有些老人明确希望住在自己家里；另一些人可能只是没有同住条件、支付不起机构或保姆、子女在外地。

`living alone` 必须继续区分：

- 主动选择；
- 妥协选择；
- 缺乏替代方案；
- 配偶去世后的被动状态；
- 暂时状态。

### 2. 不要把“有孩子”写成“有照护”

成年子女可能有意愿，却受距离、工作时间、健康、住房和自己的育儿责任限制。

### 3. 不要把“安装设备”写成“风险已解决”

2018 济南材料已经明确提供反例：设备可以成为摆设，甚至在真正跌倒的位置够不到。

### 4. 不要把“监测更密”自动写成“生活更好”

摄像头、红外、门磁、床垫和活动轨迹都会扩大可见性，也会改变家庭隐私。

必须区分：

- 老人明确同意；
- 家属觉得放心；
- 老人自己是否感到自在；
- 监测数据是否真的有人看；
- 异常是否真的有人响应。

### 5. 不要用今天“智慧养老”的词倒写 2008

2008 的 96156、固定电话、社区热线和 2009 的 CDMA/全球眼应按当时的系统名和实际工作流描述。

## 十、尚未确定

1. 2000 年以前中国城市社区紧急呼叫/电话问安服务的精确起点与规模；
2. 2007—2012 各地“一键通”设备的具体协议、硬件供应商和实际故障率；
3. 96156 等平台的呼叫中心后台如何记录 `received / dispatched / arrived / closed` 状态；
4. 政府公布的安装量与长期活跃使用量之间的差距在不同城市有多大；
5. 独居老人是否因这些系统推迟了与子女同住或入住机构，目前缺乏足够因果证据；
6. 智能摄像头/传感器在普通家庭的自费采用率与社会分布；
7. 2020—2022 疫情时期，哪些服务真正因为远程调度而保持连续，哪些只是宣传性“线上养老”；
8. 老人本人、成年子女和社区工作人员对“安全 vs 隐私”的偏好是否系统性不同。

## 十一、它改变了我们对“普通人怎么活着”的哪一点理解

过去把养老理解成“和孩子住”或“去养老院”，会漏掉越来越大的一块生活空间。

真实家庭可能是：

- 92 岁老人坚持住自己的老房子；
- 女儿每天下班再绕过去；
- 白天没人时，社区知道她是谁；
- 床头有按钮；
- 门上有传感器；
- 一个异常会同时通知子女、网格员和服务中心；
- 真出事以后，仍要某个人打开门、把她扶起来、送到医院。

因此居家养老越来越像一种**分布式照护系统**。

Internet 和智能设备真正改变的，不是“老人终于不需要别人照顾了”，而是：

> **一个家庭开始有更多办法，把“我现在不能在你身边”与“如果你出事，我希望尽快有人知道并赶到”同时维持住。**

这使“成年子女必须与父母同住”不再是唯一可执行的照护结构，也使“老人继续住在熟悉社区”多了一些现实支撑；但它从未消除照护最后必须落到某个真实身体上的事实。
