# 从墓地到数字身后事：哀悼可寻址性、纪念持久性与身后账号治理（中国，1980—2026）

## 研究问题

这份笔记研究的不是“网上祭扫什么时候出现”，也不是把死亡本身做成猎奇对象，而是一个非常普通、却会在几乎每个家庭中出现的问题：

> **一个人去世以后，分散在不同地点、不同关系网络中的生者怎样知道、找到、保存、继续访问关于这个人的记忆；当记忆开始依赖网站、账号、手机号、云端文件甚至 AI 合成时，谁又要负责让这些东西继续存在、正确存在，或者决定它们应该消失？**

它与本仓已有专题相邻但不重复：

- `communication-and-the-cost-of-living-far-away` 研究远距离家庭联系；
- `from-lost-contact-to-recontactability...` 研究活人之间的重新联系；
- `from-pseudonyms-to-identity-portfolios...` 研究一个活人怎样维护多个公开身份；
- 本文研究的是 **人在死亡以后，关系、纪念地点、账号、凭据和数字材料是否还能继续指向同一个人，以及这套“身后连续性”由谁维护。**

对应 `old-web-archaeology` companion note：

- `docs/ONLINE_MEMORIAL_VIRTUAL_CEMETERY_AND_POSTHUMOUS_MEMORY_STATE_GAPS_2000_2015.md`

## 一、先拆开几个经常被混成一个词的状态

“逝者在网上仍然存在”至少可以指六种完全不同的事情：

```text
现实中的人去世
→ 亲友仍保留纸质/实物记忆
→ 亲友主动建立纪念页
→ 生前已有账号继续可见
→ 平台把账号改成纪念状态或允许继承/管理
→ 旧账号、手机号、云端或生成式模型继续产生新的“数字存在”
```

因此必须固定这些边界：

```text
纪念页存在 ≠ 家属同意建立
页面长期在线 ≠ 平台承诺的“永久”已经兑现
账号仍可登录 ≠ 逝者希望它继续存在
手机号仍能收到验证码 ≠ 新持有人拥有旧账号
数字形象相似 ≠ 逝者本人曾说过或同意这些内容
网上献花/留言 ≠ 完整替代线下祭扫
网络祭扫人数 ≠ 全部哀悼人口
```

本文使用几个工作概念：

- **mourning addressability / 哀悼可寻址性**：亲友即使不在墓地、不在同一城市，仍有一个可以找到、进入并表达纪念的地址；
- **remembrance-place decoupling / 纪念—墓地解绑**：对逝者的记忆和仪式不再必须与同一物理地点绑定；
- **continuing-bond interface / 持续关系接口**：照片、留言、虚拟供品、年谱、音视频等允许生者继续以“对逝者说话”的方式维持关系；
- **memorial persistence gap / 纪念持久性缺口**：页面宣传的“永久保存”与域名、公司、收费、数据库和媒体资源能否长期活着之间的差距；
- **digital bereavement administration / 数字丧亲行政劳动**：亲属在死亡之后需要识别账号、找凭据、申诉、导出、保留、删除、解绑和处理数字财产/隐私的工作；
- **mortality–credential mismatch / 身故—凭据寿命错位**：人的生命结束了，但手机号、密码重置链、账号和第三方绑定仍按活人逻辑继续运作；
- **synthetic-memory authenticity gap / 合成记忆真实性缺口**：生成式图像、语音、数字人可能在“更像活着”时反而改写口音、皱纹、表情或说话内容；
- **reversible memorialization / 可逆纪念**：保留原始照片、录音和文字，同时允许后代拒绝、删除或撤回某种数字重建。

# 二、互联网以前：死亡本来就需要一套通信与共同在场基础设施

## 1. 墓地和家庭仪式不仅是“地点”，也是关系的汇合点

互联网没有发明纪念，也没有发明远距离传递家庭急事。互联网出现以前，普通家庭已经依赖邮政、电话、电报、报刊、单位和熟人网络来传递重大生活信息；祭扫、葬礼和家庭追思则把原本分散的关系重新拉到一个共同时间和地点。

一项对北京电报业务的后期行业回访提供了一个通信能力基线：1985 年以前，北京个人电报业务高峰时每月超过 300 万份；老报务员回忆的家庭电文包括“家有急事，速回”“母子平安”等。它不能单独证明具体家庭怎样报丧，但足以说明在大众移动通信和互联网以前，**紧急家庭消息已有一套按字付费、强调速度的远程通道。**

来源：

- 北京晨报 / 中国新闻网，2016-12-08：<https://www.chinanews.com.cn/m/sh/2016/12-08/8086897.shtml>

证据：**C/B-C，后期对长期电报劳动者与业务量的回访；用于通信基线，不用于推断每个家庭的丧事流程。**

### 这一层的关键约束

如果一个亲属远在另一座城市，前互联网时期至少要连续解决：

```text
消息怎样到达
→ 对方能否及时请假/买票
→ 身体能否赶到
→ 仪式是否还在
→ 以后每年是否能再回到墓地
```

所以传统墓地非常稳定，却也高度 **place-bound**。死亡后的关系不是不存在，而是经常需要交通、共同时间和亲属组织才能重新汇合。

本文在这一阶段不声称中国城市家庭已经存在大规模“远程祭祀”；相反，目前缺少足够系统的 1970s—1980s 普通家庭丧事通知、异地奔丧和周年祭扫的量化材料，这应作为后续田野和报刊检索缺口保留。

# 三、2000—2004：网站已经可以造“纪念地址”，但存在不等于有人用

## 2. 2004 年重庆是一个很重要的反例：功能先出现，日常习惯没有立即跟上

2004 年《重庆晚报》报道，南山龙园在前一年清明开设网上纪念业务，安放 4000 余具骨灰的园区里，只有 12 名普通人建立网络纪念馆；江南殡仪馆更早在 2001 年开设类似服务，却没有用户，亏损后在 2004 年取消。

报道描述，当时的网络纪念馆已经可以献花、点歌、点烛、上香、祭酒、留言和查看相册。

来源：

- 《重庆晚报》/搜狐，2004-03-25：<https://news.sohu.com/2004/03/25/99/news219599967.shtml>

证据：**B，同时代地方报道。**

这条材料特别适合本仓的方法论，因为它同时证明了两件事：

```text
service exists = true
mass behavioral integration = false / not demonstrated
```

也就是说，2001—2004 年中国已经不能被写成“网上祭奠尚不存在”，但也不能因为几个陵园有网页就写成“普通人已经开始在网上扫墓”。

## 3. 2004 年合肥留下了具体 historical locator

同年合肥大蜀山文化陵园与“网同纪念”相关报道留下了两个很有价值的地址：

- `http://www.dashushan.netor.com`
- `http://www.netor.com`

同时代报道说，用户可以按逝者姓名建立纪念空间，并进行点烛、点歌、献花、祭酒、相册和纪念文章等操作。

来源：

- 江淮晨报 / 新浪，2004-03-30（historical locator）：<https://news.sina.com.cn/c/2004-03-30/02152172262s.shtml>

证据：**B，同时代媒体；可以证明 URL 与宣传/操作描述，不等于已经取得历史 HTML transaction。**

### 新机制：mourning addressability

这里最深的变化不是“烧纸变成点击按钮”，而是纪念第一次可以获得一个互联网地址：

```text
逝者姓名
→ 一个可分享 URL
→ 外地亲友也能找到
→ 留言、照片、文章在同一地址积累
```

墓地地址依然存在，但生者之间开始多出一个不要求身体到场的共同纪念入口。

# 四、2005—2012：扩张型未来——互联网被想象成跨越空间并保存“永恒”的纪念容器

## 4. 2008 年林良英：外地同学朋友不必全部赶到同一个墓地

2008 年《南都周刊》跟访 27 岁广州人林良英。妹妹因癌症去世一年后，他付费建立网络纪念馆，一个直接目的就是让外地同学、朋友也能方便祭祀。第一个清明前夕，他看到纪念馆换上清明版式，亲友在那里献歌、点烛、留言。

来源：

- 《南都周刊》/新浪，2008-04-09：<https://news.sina.com.cn/c/2008-04-09/164415322655.shtml>

证据：**B，同时代深度报道，含当事人第一人称。**

这是一条很强的普通人生证据。它不是“网民喜欢新鲜技术”的故事，而是一项非常具体的家庭协调变化：

```text
妹妹去世
→ 同学朋友地理分散
→ 家属建立共同纪念地址
→ 清明当天不用全部完成长距离移动
→ 仍可在同一页面留下可见痕迹
```

我把它称为 **remembrance-place decoupling / 纪念—墓地解绑**。

## 5. 持续关系接口：有些人不是“一年祭一次”，而是在页面里继续照顾逝者

同一篇 2008 年报道还写到，一些家属会反复在纪念馆里给逝者送虚拟饭菜、留言，并和其他丧亲者形成松散互助。另一项对英语 Web 虚拟墓园的早期学术研究也提供了跨国对照：研究者编码了 276 个网络纪念页，其中 28.3% 的文字直接写给逝者，而不是只写给其他读者。

海外来源：

- Pamela Roberts & Lourdes Vidal, “Perpetual Care in Cyberspace: A Portrait of Memorials on the Web”, *Omega*, 2000：<https://journals.sagepub.com/doi/10.2190/3BPT-UYJR-192R-U969>

证据：**A/B（学术研究，样本为三个英语虚拟墓园）。**

这说明“对逝者继续说话”并不是中国网上祭祀独有，也不只是把线下仪式搬到屏幕。网络纪念空间还可以变成 **continuing-bond interface / 持续关系接口**。

## 6. 但同一个 2008 年已经出现“数字永恒”的硬反例

网上纪念服务当时常把跨时间、跨空间和长期保存当作卖点。《中国青年报》却在同年直接记录消费者的担忧：如果已经付钱，而网页或公司突然消失，用户该向谁追索？报道还指出，多数网上纪念服务收费不低，且这种方式当时尚未成为清明祭扫主流。

来源：

- 《中国青年报》，2008-04-07：<https://zqb.cyol.com/content/2008-04/07/content_2132646.htm>

证据：**B，同时代调查报道。**

这构成一个极其重要的早期反例：

```text
数字页面看起来不腐烂
≠
承载它的公司、域名、数据库和收费关系不会死亡
```

因此本轮新增 **memorial persistence gap / 纪念持久性缺口**。

扩张型未来真正的时间想象是：“只要上传，记忆就可以无限延长”；而现实从一开始就已经要求有人继续付费、维护账号、保存域名和数据库。

# 五、海外前 Web 对照：网络社区在 Web 以前就必须处理成员死亡与共同记忆

## 7. The WELL：死亡、删除和共同体记忆的问题早于大众 Web

The WELL 1985 年上线。关于其早期社群的 1990s 同时代/近同时代报道记载，活跃成员的死亡很早就迫使社区讨论如何纪念已故成员；1995 年病重成员 Tom Mandel 还在网上与社群持续交流，社区本身成为临终和告别关系的一部分。另一名早期成员在死亡前大量删除自己的旧发言，给共同记忆留下明显空洞。

来源：

- *Wired*, 1997, The WELL history/features：可从 Wired 旧文档与 WELL 相关档案检索（本轮以媒体历史材料作为 B 级来源）；
- Ars Technica, 2011, retrospective history of early online social networks（C/B-C，用于定位）。

证据：**B/C，需在后续若写成专门海外 case 时继续回到 WELL 原始 conference logs / archives。**

这里最值得比较的不是死亡细节，而是机制：

> **只要社区把人的文字长期积累成公共记忆，“这个人死后谁还能看、谁能删、删掉会不会伤害其他人的共同历史”就已经出现。**

这不是 Facebook、微信或智能手机才产生的问题。

## 8. 2004 年研究进一步说明：网络纪念通常是“增加一层”，不是替代全部线下哀悼

Pamela Roberts 2004 年综合 Web memorial、guestbook 与纪念页作者调查，认为网络纪念往往会支持持续关系、强化生者之间已有关系，也能形成新的丧亲者社群；研究并不把它描述成传统哀悼活动的简单替代品。

来源：

- Pamela Roberts, “The Living and the Dead: Community in the Virtual Cemetery”, *Omega*, 2004：<https://journals.sagepub.com/doi/10.2190/D41T-YFNN-109K-WR4C>

证据：**A/B，学术研究。**

跨国共同机制因此可以先写成：

```text
physical ritual remains
+
remote searchable memorial layer appears
+
community memory becomes partly platform-dependent
```

# 六、2015—2019：拥堵型未来——不是“去建纪念馆”，而是普通账号自己变成了遗产

## 9. 2019 年“互联网身后事”：人的日常账号开始比本人活得久

2019 年《中国新闻网》关于数字遗产的同期报道已经不再主要问“要不要建一个网上墓地”，而是问：QQ、微信、微博、支付宝、云盘、游戏账号在人死后该怎么办？报道区分具有经济价值的数字财产与承载个人、联系人隐私和情感记忆的社交/文件资料，并引用 2018 年德国联邦最高法院 Facebook 账号继承判决作为比较。

来源：

- 中国新闻网 / 人民网，2019-05-07：<https://industry.people.com.cn/n1/2019/0507/c413883-31071387.html>

证据：**B，同期法律/社会议题报道。**

这里出现了一个质变：

```text
2000s：家属主动创建 memorial account
2010s：逝者生前的 ordinary account 自己成为 memorial / archive / estate problem
```

一个人的照片、聊天、联系人、支付余额、云端文档和游戏资产原本只是日常使用痕迹，死亡以后却突然需要重新分类：

- 哪些能继承？
- 哪些只能纪念？
- 哪些涉及第三人的隐私？
- 谁能证明自己有权访问？
- 平台账号所有权和其中内容的权利是不是同一件事？

这就是 **digital bereavement administration / 数字丧亲行政劳动**。

## 10. 拥堵型未来的新负担：一个人留下的“数字房间”太多了

传统遗物往往集中在住宅、文件柜和银行体系；数字痕迹却可能分散在几十个平台、旧手机号、邮箱、网盘、游戏和支付工具里。

所以丧亲后的工作开始变成一个 inventory problem：

```text
先知道他用过哪些服务
→ 再找到账号标识
→ 找到手机号/邮箱/恢复凭据
→ 向平台证明死亡和亲属/继承关系
→ 区分财产、纪念、隐私和第三方通信
→ 决定导出、保留、冻结还是删除
```

**遗产变多不一定意味着“留下更多”；也可能意味着生者要维护更多无人再能亲自说明意愿的状态。**

# 七、2020—2022：偶发型未来——当身体不能到场，远程祭扫从“可选新潮”变成 continuity fallback

## 11. 2020 年谢先生：网上家庭追思会承接一次不能正常到场的清明

2020 年疫情期间，北京的谢先生和家人计划在网上为父母开家庭追思会，上传照片、留言，并向父母“汇报”家里的近况。报道当时显示，北京 2020 清明网上祭扫平台开通后已有 4400 余名用户。

来源：

- 北京晚报 / 人民网，2020-03-29：<https://bj.people.com.cn/n2/2020/0329/c82840-33911923.html>

证据：**B，同时代报道，含普通家庭第一人称。**

这条材料与 2008 年非常不一样：

- 2008 是“多一种更方便的方式”；
- 2020 是“原来的到场路线突然可能不可执行”。

因此这里更准确的概念是 **mourning continuity fallback / 哀悼连续性后备**。

## 12. 代祭 + 视频：真正的替代并不是“把一切都虚拟化”

2020 年新华社报道河北一村的异地务工者要现科。他在广东东莞工作，通过村微信群得知可以委托志愿者免费代祭，提前预约；志愿者在墓地完成实际祭扫，同时与外地村民视频通话。

来源：

- 新华社 / 羊城晚报转载，2020-04-03：<https://news.ycwb.com/2020-04/03/content_739218.htm>

证据：**B，同时代现场报道，含当事人第一人称。**

这说明疫情下真正有效的路径常常是 **hybrid ritual continuity / 混合仪式连续性**：

```text
家属不能移动
+
墓地仍是物理对象
+
本地人代理身体劳动
+
微信完成预约/通知
+
视频让远方家属同步看到
```

不是“线下祭扫被互联网取代”，而是原来必须由一个人同时完成的几件事被拆给不同的人和媒介。

## 13. 2020 的压力测试不能被倒写成长期偏好

2020 年北京清明期间，现场祭扫人数同比大幅下降，代祭扫和网上祭扫明显增长；这主要是在特定公共卫生约束下的可用替代路线。

因此：

```text
crisis adoption ≠ long-term preference
```

后面的 2025—2026 全国数据会再次证明，实体祭扫恢复后仍然占绝对多数。

# 八、2023—2026：防守型未来——问题从“能不能留下”转成“留下什么、谁能控制、它还像不像本人”

## 14. 2025 年记者“复活”外婆：数字材料越多，真实性问题反而越明显

2025 年《宁波晚报》一名记者留下了非常珍贵的同时代第一人称记录。89 岁外婆去世当天，她看到社交媒体上的“AI 复活逝者”，决定尝试制作数字人。

服务方要求至少 10 张照片和约 1 分钟音频。家人翻找旧相册和亲属手机，最后找到 2022 年的一段影像作为声音材料。生成结果却把外婆的方言变成普通话，也淡化了皱纹；记者感到技术一方面填补遗憾，一方面又在修改自己的记忆。

来源：

- 《宁波晚报》/中国宁波网，2025-04-04：<https://news.cnnb.com.cn/system/2025/04/04/030659850.shtml>

证据：**B，同时代记者亲历。**

这条材料让“数字身后事”第一次出现一个新的资源约束：**memory substrate quality / 记忆底材质量**。

```text
生前有没有照片
→ 有没有正面/不同年龄照片
→ 有没有足够长度音频
→ 音频是不是方言
→ 模型怎样修饰脸和声音
→ 输出是否仍被家属认为“是这个人”
```

数字人并不是从“真实本人”直接生成，而是从幸存的数据片段再生成。

## 15. 删除合成视频也是一种纪念选择

同一篇报道最重要的一点，是记者后来删除了 AI 数字人视频，却保留原始照片和影像。

这不能被写成“她拒绝科技”。更准确的是一种 **reversible memorialization / 可逆纪念**：

> 她愿意使用数字技术保存真实留下的痕迹，但不愿意让一个被算法改过口音、皮肤和表情的版本继续占据记忆。

因此防守型未来中的“数字纪念能力”不只是更逼真、更沉浸，也包括：

- 能看出什么是原始材料、什么是合成；
- 能撤回；
- 能删除；
- 能保留 provenance；
- 能明确谁授权生成；
- 能不替逝者说他们从未说过的话。

这形成 **synthetic-memory authenticity gap / 合成记忆真实性缺口** 和 **deceased-consent gap / 逝者同意缺口**。

## 16. 2026 年“二次放号”：人已经死亡，登录凭据却还按活人逻辑循环

2026 年《光明日报》讨论数字遗产时，用一个已故公众人物账号被新手机号持有人意外登录的事件解释更一般的制度风险：运营商回收并重新投放手机号，而第三方互联网账号仍然绑定旧号码；如果平台把“持有短信验证码”近似等同于“仍是原账号主人”，新号持有人就可能进入旧账号。

来源：

- 《光明日报》/人民网，2026-01-31：<https://society.people.com.cn/n1/2026/0131/c1008-40656802.html>
- 《检察日报》/中新网关于二次放号系统性解绑风险，2026-07-13：<https://www.chinanews.com.cn/sh/2026/07-13/10658113.shtml>

证据：**B，同期法律与行业调查。具体公众人物个案只用于说明系统机制，不扩写私人细节。**

后一篇调查进一步指出，运营商自身无法直接解绑所有第三方平台；到 2026 年，一键解绑服务已覆盖数百款常用应用，但仍不是所有服务。

这使本轮新增 **mortality–credential mismatch / 身故—凭据寿命错位**：

```text
人的生命结束
→ 手机号停止使用
→ 运营商回收号码
→ 第三方绑定未同步死亡状态
→ 号码重新分配
→ 新持有人拿到验证码
→ 旧账号可能错误地把“新凭据持有人”认成“原人”
```

死亡在民政、家庭、银行、运营商和平台里不是一个同时传播的状态。

## 17. 2025—2026 的规模数据：网络祭扫已经是稳定选项，但远没有替代身体到场

2026 年 4 月 5 日，民政部统计全国 859 个网络祭扫平台服务约 35.38 万人次，同日殡葬服务机构现场接待约 3073.40 万人次。4 月 4 日则有 857 个网络平台服务约 26.62 万人次，现场祭扫约 1928.93 万人次。

来源：

- 新华社 / 晋城市政府转载，2026-04-06：<https://www.jcgov.gov.cn/dtxx/ztzl/2026nzt/2026nqmj/qmzx_56290/202604/t20260406_2337931.shtml>
- 新华社 / 晋城市政府转载，2026-04-05：<https://www.jcgov.gov.cn/dtxx/ztzl/2026nzt/2026nqmj/qmzx_56290/202604/t20260405_2337850.shtml>

证据：**A/B，民政部统计经新华社发布。**

这里不能直接比较“每个人只用一种方式”，也不能把人次当独立个人，但数量级已经足以否定“网上祭扫取代实体祭扫”的线性叙事。

更准确的是：

> **线上祭扫已经成为基础设施中的一个稳定 fallback / supplement，而实体墓地、家庭仪式和身体共同在场仍然保持强势。**

# 九、四种时代时间感：同一技术，进入的是四种不同未来

| 时段 | 同时代问题 | 数字纪念的时间想象 | 主要风险 |
|---|---|---|---|
| 2005—2012 扩张型未来 | “网络能不能跨越距离、把记忆一直留下？” | 远方亲友可共同进入；页面似乎可永久保存 | 收费、平台死亡、域名/数据库消失、使用仍少 |
| 2015—2019 拥堵型未来 | “人留下的账号、云盘、游戏、支付和聊天到底怎么处理？” | 普通数字生活本身成为身后档案 | 账号太多、隐私与继承冲突、家属不知道有哪些资产 |
| 2020—2022 偶发型未来 | “如果今年不能到墓地，仪式还能不能继续？” | 远程/代祭/视频成为 continuity fallback | 把危机使用误写成长期偏好；线上不能代替全部身体劳动 |
| 2023—2026 防守型未来 | “留下来的东西是真的吗？谁能登录？谁能删？谁能替逝者说话？” | 更强调 provenance、权限、解绑、撤回和真实性 | AI 合成漂移、手机号重用、逝者同意缺失、账号错误继承 |

这四段不是“技术越来越先进，人越来越虚拟”的直线。

真正发生的是风险类型不断迁移：

```text
有没有入口
→ 入口能活多久
→ 入口太多谁来管理
→ 危机时能否继续
→ 长期留下的东西能否被正确控制和正确理解
```

# 十、它如何进入“普通人到底有多少种活法”的矩阵

## 教育 / 就业

丧亲可能造成请假、照护结束后的生活重组和工作中断；数字祭扫并不消灭这些成本，只可能减少某些长距离奔波。本文暂不量化 bereavement leave，后续可另开劳动制度专题。

## 住房 / 迁移

迁离故乡后，墓地不会跟着人移动。远程纪念提高了“离开祖籍地仍然能周期性参与家庭纪念”的可执行性，但没有消除回乡祭扫和实体墓地的意义。

## 婚姻家庭 / 照护

死亡之后，谁成为 memorial administrator、谁持有旧手机、谁知道密码、谁保存照片，本身就是家庭角色重新分配。数字丧亲劳动常落到少数亲属身上。

## 证件与记录

死亡不是一个自动广播给所有平台的统一 machine state。民政记录、银行、运营商、社交平台、云服务和旧手机号可能长期不同步。

## 通信方式

传统急事通知依赖熟人、单位、电话、电报和旅行；网络纪念把一个新的共享、异步地址加入其中。

## 互联网平台

平台不只是“发布纪念内容”的媒介，还承担域名、账号、数据库、媒体存储、权限、收费、密码恢复和删除政策。

## 信息获取 / 社交关系

死者的同学、同事、远方朋友有时不在核心亲属通知链里。公开或可分享的纪念地址扩大了这些弱关系获得消息与参与纪念的半径。

## 未来预期

2008 的未来可以把数字记忆想成“永恒”；2019 后普通人开始面对数字遗产；2025 后又开始问“被永久留下的到底还是不是本人”。

## 线上 / 线下身份

死亡以后，一个人的 profile 可能从“本人主动经营的身份”变成“由家属、平台和算法共同管理的对象”。同一个账号的 author、owner、administrator 和 remembered person 开始分离。

## 平台消失与记忆保存

这条题目与 `old-web-archaeology` 直接交叉：**“网络纪念馆”最强的卖点恰恰是长久，而旧网最强的经验恰恰是平台、域名、插件和数据库会消失。**

# 十一、反例：不要把“数字纪念”浪漫化成新的文明阶段

1. **2001—2004 已经有服务，但不少地方几乎没人用。** 技术可用不能推成习惯已经改变。
2. **2008 同一年既有“外地同学可以共同纪念”的真实便利，也有“网站没了找谁”的真实担忧。**
3. **2020 大规模增长发生在现场路线受限时。** 这更像 failure fallback，不等于所有人更喜欢虚拟祭祀。
4. **2025—2026 实体祭扫数量仍远高于网络祭扫。** 数字层更像 supplement。
5. **AI 生成更逼真不等于更接近真实记忆。** 方言被替换、皮肤被平滑，本身就是历史信息损失。
6. **保留越多不必然越尊重逝者。** 删除合成影像、限制公开范围、拒绝长期维持某个账号，也可能是合理的纪念选择。

---

# 十二、后见之明风险

### 1. 不把 2008 的“永久”嘲讽成技术天真

当时互联网确实把照片、文章和远距离参与放到普通家庭以前很难拥有的可共享空间里。平台后来可能死亡，不代表当时“终于能留下更多”的体验是假的。

### 2. 不把今天的数字遗产法规问题投射到早期纪念馆

2004 建纪念页的人面对的是建馆费、域名、账号和虚拟祭品；2019 以后面对的是微信、支付、云盘和游戏等一整套日常数字资产。问题结构已经改变。

### 3. 不把 2020 的危机使用当作长期选择

疫情是一次 execution stress test，而不是天然的价值偏好调查。

### 4. 不把“AI 复活”写成必然下一阶段

2025 同时代材料里既有人付费尝试，也有人拒绝；记者自己尝试后又删除。它目前更适合研究 **边界协商**，而不是宣布“数字永生时代到来”。

### 5. 不把公共纪念页面当作全部悲伤

最私人的悲伤、家庭争议、无人留言、忘记密码、页面停更和最终删除，本来就最难留下公开档案。

# 十四、目前不知道什么

1. **1980s—1990s 中国普通家庭报丧、奔丧和周年祭扫通信栈的分布**：电话、电报、邮政、单位通知各自占多大比重，目前缺系统材料。
2. **2000—2010 早期网上纪念馆的真实留存率**：创建多少、几年后还剩多少，运营商自己的累计数字不能直接当存活率。
3. **早期用户的续费/忘密/删馆率**：这大多是后台私人状态。
4. **虚拟供品按钮真实 transaction**：当前只有报道和现存 legacy shell，尚未验证 2004/2008 原始 DOM、form、session、charset 与后端。
5. **死亡以后普通社交平台账号的实际家庭处理率**：媒体法律讨论远多于代表性家庭调查。
6. **不同年龄、城乡、迁移距离对网络祭扫使用的影响**：全国“人次”数据不足以回答是谁在用。
7. **AI 数字人的长期使用**：2025 的报道只能证明出现与争议，不能证明它会成为常态。

# 十五、下一步最值钱的原始材料

- 2000—2010 `netor.com`、`dashushan.netor.com` 或其他网上纪念馆的可验证 Wayback/WARC capture；
- 早期帮助页、收费规则、续费/过期政策、删除和密码找回说明；
- 2007—2010 普通纪念馆公开页面的多时点 capture，用于判断页面究竟怎样衰减；
- 2018—2019 同时代普通人讨论“父母/伴侣账号死后怎么办”的论坛或问答原帖；
- 2023—2026 普通家庭自己的数字遗产清单、账号处理和删除选择的第一人称材料；
- 能区分“线上作为唯一替代”“线上+线下混合”“只线下”的调查数据。

隐私 stop condition：**不为了补完数字遗产而重新识别普通逝者、拼接已删除社交账号、恢复私人聊天或寻找不应公开的遗属联系方式。**

# 十六、这一轮改变了我们对“人怎么活着”的哪一点理解

死亡本身没有因为联网而变得可逆。

改变的是死亡以后生者要处理的关系结构：

```text
过去更重要的是：
谁得到消息、谁赶得回来、谁能到墓地。

后来又增加：
谁能找到同一个纪念地址、
谁维护页面、账号和域名、
谁能进入逝者的云端与社交账号、
谁有权保存或删除、
以及一个由算法生成的“他/她”到底还能不能代表本人。
```

因此“普通人有多少种活法”还应包括一个常被忽略的尾部条件：

> **一条人生不仅要看活着时能进入多少教育、工作、家庭和迁移路线，还要看它结束以后，留下来的关系和记录能否被生者继续理解、照料和正确关闭。**

数字技术扩大了哀悼的可寻址范围，却也把以前会随肉身一起结束的一部分维护责任，交给了平台、凭据和后来的人。

---

## 本轮阶段判断

这是一个此前矩阵未独立建模的新增生活路径/制度接口：**丧亲后的数字管理与身后身份连续性**。它同时带来新的通信转折机制、旧网保存偏差、跨国前 Web 对照和 2008 / 2019 / 2020 / 2025—2026 的同期证据。

因此本轮属于 **substantive new evidence / mechanism**，连续“无实质新增”计数维持 **0**，不进入阶段 closure。
