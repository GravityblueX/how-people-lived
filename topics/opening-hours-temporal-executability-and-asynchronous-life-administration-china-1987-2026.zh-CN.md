# 从“请假办事”到“下班也能办”：营业时间、时间可执行性与异步生活行政，中国 1987–2026

## 研究问题

普通人“有多少种活法”，不只取决于一项服务是否存在、本人是否符合资格、是否付得起钱，还取决于一个常被技术史和制度史忽略的问题：

> **这件事开放的时候，我本人有没有空？**

如果银行、报名点、办证窗口、招聘会、学校确认点和单位都在相同的工作日白天运行，那么一个已经上班或上学的人，理论上拥有一项权利或机会，并不等于她能无成本地执行它。

本笔记把这个问题称为 **temporal executability（时间可执行性）**：

```text
formal eligibility / 制度上有资格
+ service exists / 服务存在
+ spatial access / 到得了
+ technical access / 技术上能进入
+ temporal compatibility / 开放时间与本人可支配时间相容
→ life route is actually executable / 人生路线才真正可执行
```

并把“本人可支配时间与机构开放时间不重合，因此必须请假、逃课、换班、托人、排早队或放弃”的成本称为 **schedule-conflict tax（时刻冲突税）**。

这和仓库已有的“scheduled information → ambient information”不同。那里研究信息何时抵达人；这里研究的是：

> **制度动作什么时候允许由人发起、什么时候真正进入后台、什么时候才改变现实状态。**

它也和“申请组合 / route multiplexing”不同。一个人可以同时想考研、求职、考证、换证、缴费；本笔记问的是这些路线是否能被塞进同一周的时间表，而不要求她为了每一项都退出当前学校或工作。

## 一、先拆状态：24 小时入口不是 24 小时完成

研究任何“网上办 / 24 小时 / 不打烊”材料时，至少拆成：

```text
service advertised
→ front-end reachable now
→ user can authenticate now
→ required materials are ready now
→ form/request can be submitted now
→ server has durably accepted it
→ payment/confirmation succeeds
→ request enters a queue
→ human or automated review occurs
→ result is generated
→ user encounters the result
→ real-world state changes
```

因此必须固定以下边界：

- `online ≠ 24-hour`；
- `24-hour submission ≠ 24-hour review`；
- `request submitted ≠ durable record`；
- `durable record ≠ accepted eligibility`；
- `reservation can be made anytime ≠ legal/physical act can occur anytime`；
- `24-hour self-service zone ≠ every service is available there`；
- `time-shifting ≠ time-saving`。

最后一条尤其重要。一个网申表如果仍然要填三小时，它可能没有节省时间，只是允许把三小时从工作日下午移动到晚上。

## 二、Internet 以前：先出现的是“机器时间”与“收件箱时间”

### 1. ATM：把取款从柜员的时间表里拆出来

1970 年代以前，银行业务通常高度依赖营业时间。IBM 的 ATM 历史说明，1972 年 Lloyds Bank 与 IBM 推出的 2984 Cashpoint 把 24×7 自助银行变成现实：机器可以在柜员不工作的时段继续执行部分交易。

这说明 **opening-hours decoupling（开放时间解绑）** 并不需要 Web。

但 ATM 也提供了一个重要边界：早期机器通常只承接一小部分银行状态。它不能被解释为“银行整体从此 24 小时工作”。

### 海外证据

- **B/C（厂商机构史，后期整理）**：IBM, *The ATM*；1972 Lloyds/IBM 2984 与 24×7 banking。  
  <https://www.ibm.com/history/atm>

### 2. 中国 1987：没有大众 Internet，不等于没有数字化的时间解绑

中国银行资料记载，1987 年在珠海发行第一版长城提款卡，并投入 ATM 服务；同时明确说明，因为当时电脑通讯设备不足，尚未实现全辖联网，只限珠海当地储蓄所使用。

这组材料非常适合校正两个相反的错误：

1. 不能把 1994 年以前写成“完全没有数字通信 / 电子自助服务”；
2. 也不能把一个地方性的 ATM 网络写成普通家庭已经拥有全国联网银行或 Internet banking。

更准确的阶段是：

```text
bank counter only
→ local machine-assisted self service
→ regional interconnection
→ wider card network
→ Internet/mobile banking
```

这里 Internet 还没有进入，但“存取款必须碰到柜员营业时间”已经开始被机器削弱。

### 中国证据

- **B/C（中国银行后期机构史）**：《中国第一张ATM提款卡》；1987 珠海首发，设备不足、未全辖联网，只限当地储蓄所，ATM 打破必须到银行办理存取款的传统。  
  <https://www.bankofchina.com/aboutboc/ab5/200811/t20081119_11892.html>
- **B/C（中国银行后期机构史）**：《顺应改革开放需要，开创中国信用卡先河》；1987 珠海第一批 ATM，1992 广东出现区域性联网。  
  <https://www.bankofchina.com/aboutboc/ab7/200809/t20080926_6896.html>

### 3. Email：把“对方必须此刻在线”拆掉

ARPANET 不是大众网络。Computer History Museum 记载，Ray Tomlinson 1972 年为 ARPANET 写出网络电子邮件程序并形成 `user@host` 约定；这证明的是研究/机构网络中的异步通信前史，不能外推普通家庭。

RFC 821（1982）则在协议层明确保存了一个关键时间语义：若用户此刻不活跃，邮件可以进入 mailbox，而不要求收件人与发件人在同一时刻同时出现。

这给本题提供了一个很深的对照：

> **Internet 最早的重要生活能力之一，不只是“更快”，而是让通信双方不必共享同一个时间窗口。**

### 海外证据

- **B（计算机史机构）**：Computer History Museum, Internet History, 1972 ARPANET email。  
  <https://www.computerhistory.org/internethistory/1970s/>
- **A（原始协议）**：RFC 821, 1982；当接收用户不活跃时，邮件进入 mailbox。  
  <https://datatracker.ietf.org/doc/html/rfc821>

### 4. Minitel：大众化的“下班后还可访问服务”早于 Web

法国 Minitel 又提供了一个比 ARPANET 更接近普通生活的海外对照。1980s 中期以后，家庭电话订户中的 Minitel 已经形成大规模可及性，电子目录、消息、生活服务和银行等服务在同一终端上出现。1996 年《Le Monde》回顾 Banque Directe 时，明确把 1994 年推出的 Banque Directe 描述为无柜台、24 小时可访问，并提到 Minitel、语音服务器、传真和 PC 等远程渠道。

因此不能把“制度服务在家里、非柜台时段可访问”当成 World Wide Web 独有的历史阶段。

### 海外证据

- **A/B（同期媒体）**：Le Monde, 1987；当时已有数百万 Minitel 终端，服务涵盖目录、消息、生活和银行。  
  <https://www.lemonde.fr/archives/article/1987/04/15/les-nouveaux-tarifs-de-la-telematique-le-kiosque-multipaliers-a-l-etude_3543588_1819218.html>
- **A/B（同期媒体）**：Le Monde, 1996, *La banque à domicile a pris modestement son envol en France*；Banque Directe 1994、24h 无柜台银行。  
  <https://www.lemonde.fr/archives/article/1996/11/03/la-banque-a-domicile-a-pris-modestement-son-envol-en-france_3752975_1819218.html>

## 三、1998–2004：从“机器不关门”到“网页可以先收件”

1990s 后期中国的自助银行已经把 ATM、存款机、查询终端组合成独立自助空间。1999 年新浪同期图片报道北京招商银行独立式自助银行时，直接把 24 小时存、取、查询、转账作为卖点。

这比后来的政务“24 小时自助区”早二十年形成了一个成熟模板：

```text
human counter closes
but
machine front-end remains open
```

Internet 随后把这种机器时间进一步搬到家庭/办公室电脑上，但早期 Web 并不等于所有后台都同步变成 24 小时。

### 证据

- **B（同期媒体）**：新浪，1999-08-30，招商银行北京独立式自助银行；ATM、CDM、查询终端提供 24 小时服务。  
  <https://news.sina.com.cn/china/1999-8-30/10520.html>  
  （若此 URL 后续失效，应仅作为 locator，不从 URL 本身推技术栈。）

### 新机制：front-end / back-end temporal split

网页和自助机第一次把一个制度事务分成两套时钟：

- **front-end clock**：用户什么时候可以填写、提交、查询；
- **back-end clock**：银行、单位、学校、政府人员什么时候审核、结算、制作、发证。

以后看到“全天候”“网上受理”都必须问：

> 到底是哪一只钟变成了 24 小时？

## 四、2005–2012：扩张型未来不仅是“机会更多”，也是“可以把未来塞进晚上”

### 1. 2008 广州经济资格考试：24 小时报名，但完整路线仍跨越线下和等待

2008 年广州市经济专业技术资格考试报名通知的同期转载保存了一条特别完整的状态链。报名系统在一个月左右的窗口中“24小时不间断接收”网上报名，但报名者仍需要：

```text
网上填资料
→ 打印照相凭条
→ 去指定照相馆
→ 等照片上传（可到 24 小时）
→ 等报名点网上确认
→ 查询状态
→ 网上支付
→ 打印登记表
→ 交单位审核盖章并保存到日后办证
```

因此它是 **time-shifting without full process decoupling（时间平移但未完全解绑）** 的典型例子。

上班者可以晚上填表，但照片、单位盖章、后台确认仍保留自己的时间边界。

### 证据

- **B/A-near-primary（同期转载官方通知）**：2008-04-03，广州市人事考试中心穗人考中心函〔2008〕52号。  
  <https://www.chinaacc.com/new/15/22/48/2008/4/lu113513204413480024876-0.htm>

### 2. 反例：2008–2009 研究生“网上报名”每天只开 9:00–22:00

教育部 2007、2008 年对研究生网报的同期公告明确写明：系统每天 9:00–22:00 开放，之后还必须在 11 月指定日期到现场确认、缴费、照相。

所以：

> **online ≠ 24-hour**

甚至已经是全国性网上系统，也可能仍复制一个比实体窗口长、但并非全天的营业时间。

### 证据

- **A（教育部同期公告）**：2007-09-10，2008 年硕士研究生报名，每天 9:00–22:00，之后现场确认。  
  <https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/moe_1485/tnull_26364.html>
- **A（教育部同期公告）**：2008-09-17，2009 年硕士报名仍为每天 9:00–22:00，并保留现场确认。  
  <https://www.moe.gov.cn/moe_879/moe_329/moe_1798/tnull_39054.html>

### 3. 2008 公务员网报：全天可提交也会制造“凌晨错峰”

2008 年 10 月国考网报首日，记者实际操作时遇到“系统忙”、页面长时间无响应；技术人员随后建议报考者在晚上、清晨错峰上网。

这增加了一个以前很少被当成生活史变量的状态：**off-peak application labor（错峰申请劳动）**。

数字系统理论上让你不必排实体队，但共享服务器容量不足时，人仍会把制度事务移动到别人睡觉的时段。

### 证据

- **B（同期媒体，含现场操作）**：沈阳今报 / 新浪，2008-10-16，《公务员报名系统拥堵建议报考者错峰上网》。  
  <https://news.sina.com.cn/o/2008-10-16/032914580484s.shtml>

### 4. 2008 同时代求职第一人称：网页可随时投，不等于边际成本趋近于零

2008 年校园招聘材料记录一名华南理工毕业生从 9 月起已经投出几十份网申而没有反馈，并把这种状态称为自己的“网申恐惧症”；同一时期报道还记录，部分公司的一份网申可能有十多页、耗时 3–4 小时。

这对“数字申请降低摩擦”的叙事是关键反例：

- 投递的空间成本下降；
- 可在非办公时段完成；
- 但重复填表、开放题、等待反馈会制造新的时间成本。

所以这轮引入 **asynchronous clerical transfer（异步文书劳动转移）**：过去由柜台/HR/秘书承担的一部分数据录入和标准化劳动，转到申请者自己的夜晚。

### 证据

- **B（同期媒体，第一人称）**：信息时报 / 新浪，2008-10-30；毕业生小陈自述几十份网申无反馈。  
  <https://edu.sina.com.cn/l/2008-10-30/1406154992.shtml>
- **B（同期媒体）**：长沙晚报 / 新浪，2008-11-06；网申页面和填写耗时。  
  <https://edu.sina.com.cn/l/2008-11-06/1057155891.shtml>

### 这一阶段怎样改变“未来”

扩张型未来不只意味着“网上能看到更多岗位/考试”。更细的机制是：

> **一项未来路线开始可以在当前人生的边缘时间里被维护。**

一个白天上课、实习或工作的人，可以晚上报名、查资格、投简历、打印材料，因此“当前路线”和“下一条路线”更容易短暂并行。

这增加的是 **parallel-life temporal capacity（并行人生的时间容量）**。

但它不是免费的。夜晚可以被未来计划占满。

## 五、2015–2019：拥堵型未来把“请假成本”变成显性的制度设计问题

### 1. 2019 北京东城：最直接的一句第一人称证据

2019 年《人民日报》报道北京东城 7×24 小时政务自助区时，居民李悦明确说，以前上门办事只能在上班时间，因此必须向单位请假；有自助区以后，可以在工作人员下班后办理。

这不是抽象的“互联网便利”。它把 **schedule-conflict tax** 直接说出来了：

```text
paid-work hours
overlap
public-service hours
→ citizen must sacrifice work time / leave quota
```

### 证据

- **B（同期主流媒体，第一人称）**：《人民日报》，2019-01-03，《办事大厅看变化》。  
  <https://legal.people.com.cn/n1/2019/0103/c42510-30500482.html>

### 2. 2019 上海徐家汇：24 小时前台，但企业变更仍等后台审核

徐家汇商圈 24 小时“一网通办”自助点提供 434 个事项。企业人员能扫描身份证和纸质材料提交申请，但报道同时明确：材料提交后仍要等工商部门线上审核，之后经营范围变更才生效。

这正好证明：

> **front-end 24/7 ≠ final state 24/7**

数字服务可能首先把“什么时候递交材料”的时间主权交给用户，而不是让整个官僚组织在凌晨持续人工审批。

### 证据

- **B（同期媒体）**：解放日报 / 人民网，2019-02-13。  
  <https://politics.people.com.cn/n1/2019/0213/c70731-30655103.html>

### 3. 2019 武汉：下班路上成为新的办事时间

武汉 24 小时社区政务终端的同期报道中，居民邱姣玉下午 6 点下班后办理房产登记信息，明确说自己平时无法请假；另一名市民则在下班路上打印孩子入学需要的房产证明。

这里出现的是 **commute-administration folding（通勤—行政折叠）**：

原本需要独立请半天假的任务，被折叠进下班回家的路径。

### 证据

- **B（同期媒体，政府站转载，第一人称）**：长江日报 / 武汉市政府，2019-07-14。  
  <https://www.wuhan.gov.cn/zwgk/xxgk/zcjd/mtzj/202109/t20210928_1786556.shtml>
- **B（同期媒体，第一人称）**：武汉晚报 / 新浪，2019-08-07。  
  <https://news.sina.com.cn/s/2019-08-07/doc-ihytcerm9018449.shtml>

### 这一阶段怎样改变“未来”

拥堵型未来的一个特征，不只是机会竞争变激烈，而是一个成年人同时承担：

- 全职工作；
- 换证/缴费/社保/住房事务；
- 孩子入学材料；
- 求职、考证或资格更新。

所以制度设计开始从“所有人按政府/银行/单位的时间来”向“至少部分事务由本人选择时间”移动。

这不是纯粹效率改进，而是 **institutional time sovereignty（制度时间主权）** 的重新分配。

## 六、2020–2022：偶发型未来把异步入口从便利变成连续性基础设施

2020 年武汉政务大厅未正式开放时，全市超过 97% 的政务服务事项可网上办理。同期报道保存了一个特别清楚的异步案例：3 月 14 日晚，企业在线提交新店食品经营许可证申请，第二天上午收到电子许可证。

状态不是：

```text
night submission → instant approval
```

而是：

```text
night submission
→ durable queue
→ next-day review/processing
→ electronic result
```

这就是 **asynchronous continuity（异步连续性）**。

当物理大厅关闭时，一个制度只要还能“先收件、后处理”，就可能保持生命历程和经营活动不完全停摆。

### 证据

- **B（同期媒体）**：长江日报 / 中新网，2020-04-30；武汉网上办可办率超过 97%，晚间申请次日上午发电子证。  
  <https://www.chinanews.com/sh/2020/04-30/9172164.shtml>

### 反例：数字连续不等于所有人无条件连续

这一机制仍依赖：

- 家庭/单位有设备和网络；
- 本人有账号和认证工具；
- 材料已经电子化；
- 事项本身允许网办；
- 后台人员/系统仍在运行；
- 需要的实体物流还能运转。

所以疫情中的“网上不打烊”不能被写成“大厅关闭没有影响”。

更准确的命题是：

> **异步数字入口提高了制度在空间中断时的韧性，但把连续性转移到另一套设备、账号、认证、平台和后台队列上。**

## 七、2023–2026：防守型未来开始要求“时间 fallback”而不只是一条数字主路

### 1. 2025 上海青浦：夜间窗口证明线下 fallback 仍有价值

2025 年上海青浦开设身份证“夜间专场”。同期官方材料里的倪先生说，自己白天工作繁忙，一直没能换证；谢女士则因为孩子上学时间与窗口时段冲突，直到夜间专场才在下班接孩子后办理。

这非常重要，因为它不是“所有事情 App 化”的故事。

合法身份证更新仍然可能需要：

- 人像/照片；
- 信息核验；
- 工作人员协助；
- 特殊情况处理。

因此防守型未来里的好系统，更像：

```text
online route
+ self-service route
+ evening/weekend staffed route
+ daytime full-service route
```

而不是只保留一个最先进入口。

### 证据

- **A/B（地方政府同期材料，第一人称）**：上海市青浦区人民政府，2025-05-15。  
  <https://www.shqp.gov.cn/shqp/sjtjzt/sjyw/20250521/1281525.html>

### 2. 2026 北京“不打烊”：不同时间仍然是不同服务模式

2026 年 1 月 1 日，北京市政务服务中心开始“不打烊”服务。官方说明本身就保存了一个需要严守的边界：

- 周六上午提供预约办事；
- 周六下午、周日及多数节假日主要提供咨询、接件、帮办；
- 24 小时自助区提供特定终端和取件等服务。

所以连“不打烊”都不能翻译成“所有事项 7×24 小时即时人工办结”。

### 证据

- **A/B（官方信息经央视/央广）**：2026-01-01，北京政务服务“不打烊”。  
  <https://news.cnr.cn/native/gd/20260101/t20260101_527480035.shtml>

### 新机制：temporal fallback redundancy

这轮材料把“防守”具体化成 **temporal fallback redundancy（时间后备冗余）**：

> 一项重要事务不应该只有一个与你工作/上学完全冲突的时间入口。

如果在线身份认证失败，可以去晚间窗口；如果自助机不支持复杂事项，还有周末接件；如果本人白天不能离岗，至少有另一条时间路线。

这种冗余不追求“所有服务都在凌晨三点人工处理”，而是避免一次时刻冲突就让整条人生路线失效。

## 八、一个反向历史：从“机构不等我”到“工作永远找得到我”

开放时间解绑并不只有自由的一面。

仓库已有远程工作专题已经指出，移动通信和在线办公会制造 **reachability capture（可达性捕获）**：工作不再要求身体在办公室，也可能意味着工作消息进入夜晚、周末和旅行。

本题因此必须保留一个反向命题：

```text
citizen/customer side:
service becomes available at more hours

worker side:
service may require someone/system to be available across more hours
```

异步队列、自助设备和批处理能把两者部分分开；如果没有这种制度设计，“24 小时服务”就可能只是把时刻冲突从办事者转移给夜班劳动者、客服和后台人员。

因此以后研究 24 小时基础设施时应继续问：

- 哪些时段是机器在工作？
- 哪些时段必须有人值守？
- 后台是不是批量次日处理？
- 夜班劳动被谁承担？
- 用户获得的时间自由是否对应另一群人的时间约束？

## 九、跨时期比较：四种“未来时间”

### 2005–2012：扩张型未来

核心时间机制：**把下一条路塞进当前生活的边缘时间。**

- 夜里报名；
- 晚上投简历；
- 网上查资格；
- 凌晨错峰避开服务器拥堵。

未来变多的同时，夜晚也被申请、备考和状态查询占用。

### 2015–2019：拥堵型未来

核心时间机制：**减少为了生活行政而退出工作日的次数。**

“不用请假”开始成为 24 小时政务服务的直接卖点。时间不是空闲，而是已经被工作、通勤、家庭事务挤满；制度要在缝隙里被执行。

### 2020–2022：偶发型未来

核心时间机制：**先收件、后处理，维持制度连续性。**

大厅关门不再意味着所有队列停止；但连续性开始依赖在线身份、设备、后台系统和电子结果。

### 2023–2026：防守型未来

核心时间机制：**保留多种时段和多种渠道的 fallback。**

成熟目标不是“所有人都必须线上”，而是避免：

- 只在白天可办；
- 只在 App 可办；
- 只在自助机可办；
- 只在某个单位批准请假后才可办。

## 十、重点矩阵：它改变了哪些“活法”

| 生活领域 | 时间接口如何约束路线 | 异步/延时服务可能改变什么 |
|---|---|---|
| 教育 | 报名、确认、缴费与上课/工作冲突 | 允许在夜间维护升学路线，但现场确认仍可能同步 |
| 就业 | 招聘会、面试、网申、资格审查 | 当前工作与下一份工作可短暂并行；网申也会吞噬夜晚 |
| 住房 | 产权查询、材料打印、贷款/公积金事务 | 下班后可处理部分事务，减少请假 |
| 婚姻家庭 | 婚登预约、孩子入学材料、家庭成员证件 | 家庭事务更容易折叠进通勤/晚间 |
| 迁移 | 身份证、护照、签注、跨地证明 | 迁移和旅行准备不必总占用工作日 |
| 照护 | 白天照护责任使窗口时间更难兼容 | 夜间/网上入口扩大照护者可执行时间 |
| 非正规劳动 | 没有稳定请假制度的人更怕窗口冲突 | 非工作时段服务可能比对白领更重要 |
| 长期中断 | 待业者时间多但制度时钟仍存在 | 异步系统不必然只服务“时间贫困者” |
| 证件与记录 | 证件到期、档案/登记有截止日 | 多时段入口降低一次时刻冲突导致路线断裂的概率 |
| 通信 | 同步电话/现场要求双方同时可达 | 邮箱、留言、队列让双方时间解耦 |
| Internet 平台 | 系统本身有开放时段、负载和截止时间 | “在线”开始形成独立的机器营业时间 |
| 信息获取 | 公告可随时看，不等于事务可随时办 | 信息层先于交易层实现全天候 |
| 社交关系 | 即时通信提高随时可达性 | 时间自由也可能反转成回应义务 |
| 未来预期 | 下一步计划必须占用当前生活时间 | 更多未来可在晚上被维护，增加并行路线容量 |
| 线上/线下身份 | 夜间自助常依赖身份证、人脸、账号 | 身份认证成为“非人工时段”能否开放的前提 |
| 平台消失与记忆 | 说明页容易保存，真实夜间 transaction 不易保存 | 后人容易高估“24h”实际完成能力 |

## 十一、证据等级、反例与后见之明风险

### 可以较有把握写出的事实

1. **B/C**：1987 年中国已有地方性的 ATM 自助服务，但设备和联网能力有限，不能外推全国或 Internet banking。
2. **A**：1982 RFC 821 的邮件语义已经允许收件人不活跃时把消息进入 mailbox；这是异步通信协议的一手证据。
3. **A/B**：2008 年中国不同网上报名系统的开放时间并不统一：有 24 小时系统，也有每天 9:00–22:00 的全国性系统。
4. **B**：2008 国考报名首日拥堵，技术人员建议夜间/清晨错峰。
5. **B + first-person**：2008 求职者已经出现大量网申无反馈和单次填写数小时的时间负担。
6. **B + first-person**：2019 年多地 24h 政务服务明确以“无需请假 / 下班可办”为用户价值。
7. **B**：2020 武汉可观察到晚间线上提交、次日上午后台完成的异步处理链。
8. **A/B + first-person**：2025 夜间身份证窗口仍解决真实的工作/上学时段冲突。
9. **A/B**：2026 “不打烊”政务中心仍按时间分层提供预约、咨询接件和 24h 自助，不是所有状态在任何时刻等价。

### 反例

- Internet 出现以前 ATM、电话银行、Minitel、email 已经能制造时间解绑；所以不能写“Web 发明 24 小时服务”。
- 网上报名可能每天只开 9:00–22:00；所以不能写“网上 = 全天候”。
- 24h 表单可能仍要第二天人工审核；所以不能写“全天提交 = 即时完成”。
- 网申可能比纸表更长；所以不能写“线上 = 必然省时间”。
- 夜间自助不能覆盖复杂事项；所以不能把全渠道 fallback 简化成 App 替代窗口。
- 延长服务时间可能把时间成本转移给夜班劳动者；所以用户时间自由不等于社会总时间成本下降。

### 后见之明风险

1. **不要把今天的 7×24 App 心智投射到 2000s Web。** 当年很多网站有固定开放窗口、人工审核、照片上传延迟和现场确认。
2. **不要把“报名窗口持续一个月”写成“任何时刻可操作”。** 需要看每日开放时段、服务器负载、截止规则。
3. **不要把“用户可以夜里提交”写成“机构夜里有人处理”。**
4. **不要把一个城市的 24h 终端外推全国。** 城市、事项、设备分布差异很大。
5. **不要把 ARPANET 的异步邮件外推普通家庭。** 它是全球 Internet 前史和协议机制证据，不是大众生活普及证据。
6. **不要把 ATM 地方试点写成普通人普遍获得时间自由。** 机器数量、卡持有、城市分布、网络互联和可交易类型都要分别证明。

## 十二、尚未确定

- 1990s 中国普通家庭第一次大规模感受到“非银行营业时间也能处理金融事务”的地区和人群分布，还缺更好的同期用户材料。
- 1998–2005 早期网银、报名和政务网站的真实每日开放时段是否稳定，仍需更多历史帮助页或 capture。
- 2008 广州考试报名的原始 `gzexam` 页面、DOM、charset、session、服务器时钟和过载状态，本轮没有验证 WARC/Wayback capture。
- 不同职业中，“请半天假办一件证件/银行/住房事务”到底占多少年工作时间，缺少可比的量化序列。
- 24 小时用户入口把多少夜班劳动转移给后台客服、运维和审核人员，需要劳动史材料才能回答。
- “下班可办”对没有稳定劳动合同、不能自由请假的工人是否比对白领更重要，目前材料仍偏城市正式就业者。
- 2015–2019 与 2023–2026 的全国分布还不能只用几个城市的示范案例替代。

## 十三、下一步可验证假说

### 假说 A：Internet 最先扩大的未必是服务总量，而是“制度事务可被安排到一天中的更多时段”

验证方法：比较同一事务在纸面/柜台、早期 Web、移动端三个时期的每日开放时间、必须现场环节和后台处理时延。

### 假说 B：时间解绑会提高“在不退出当前路线的情况下准备下一条路线”的能力

验证对象：在职考证、在职考研、边工作边求职、异地申请。

注意：这不能仅凭报名网站上线推因果，需要同期第一人称说明“若只能工作日现场办理会怎样”。

### 假说 C：成熟数字制度不是完全实时，而是更擅长安全地排队

真正有韧性的系统可能不是所有人在 03:00 实时办公，而是：

```text
03:00 user can submit
→ request is durably timestamped
→ queue survives overnight
→ 09:00 backend continues
→ user can later inspect status
```

这比“永不关门”的宣传语更值得作为历史机制研究。

## 十四、这一轮改变了什么理解

过去我们常问：

> 一个人有没有资格去考、去办、去申请、去迁移？

现在还必须再问：

> **她必须在哪一天、几点钟出现？那几个小时是否已经属于学校、雇主、孩子、老人或通勤？**

因此普通人的未来菜单不仅有“资格边界”，还有 **时间边界**。

从 ATM、邮箱、Minitel、早期报名网站，到 24 小时政务终端和夜间窗口，长期变化不是简单的“社会越来越快”，而是：

> **越来越多制度动作不再要求普通人的身体、机构工作人员和信息系统在同一小时同时出现。**

这增加了一种很具体的自由：不必为了维持下一条人生路线，先从当前生活里请半天假。

但它也创造了新的风险：夜晚会被申请、表格、消息和工作继续占用。因此真正值得追踪的不是“全天在线”，而是 **谁获得了移动任务到另一个时段的权力，以及谁因此失去了真正关闭的时段。**
