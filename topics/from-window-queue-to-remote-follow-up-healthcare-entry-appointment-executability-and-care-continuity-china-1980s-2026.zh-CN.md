# 从凌晨排队到远程复诊：就医入口、预约可执行性与医疗连续性（中国，1980s–2026）

## 研究问题

这篇 note 补普通生活矩阵里一个此前没有单独建模的约束：**一家医院存在、某位专家出诊、甚至网页上出现“预约挂号”按钮，都不等于一个具体的人已经获得了可执行的医疗机会。**

真正的任务链至少是：

```text
身体出现问题
→ 判断是否需要就医
→ 找到合适层级的医疗机构
→ 判断科室 / 专业
→ 找到挂号或预约入口
→ 满足身份、电话、就诊卡等条件
→ 在稀缺号源中取得一个可用时段
→ 能按时到院，或满足线上诊疗适用条件
→ 完成报到 / 取号 / 候诊
→ 医生实际接诊
→ 检查、检验、处方或治疗可以继续执行
→ 需要复诊时，前次记录可以被重新找到
→ 支付 / 医保 / 药品取得等后续环节能够闭合
```

本文使用几个工作概念：

- **care-entry addressability / 就医入口可寻址性**：普通人是否知道应该找哪家医院、哪个科室、哪个入口；
- **appointment executability / 预约可执行性**：预约制度存在以后，本人是否真的能拿到合适、可到达、可使用的号；
- **diagnostic-routing burden / 诊疗路由负担**：在专业分科体系中，患者是否必须先正确判断自己该挂哪个科；
- **queue virtualization / 队列虚拟化**：等待从挂号窗口前的身体队伍，转成电话忙线、网页刷新、放号时点、身份验证与后台队列；
- **scarcity relocation / 稀缺迁移**：数字化改变获得稀缺资源的方式，却不会自动增加专家时间、床位或检查容量；
- **first-visit / follow-up split / 初诊—复诊分裂**：线上医疗对已有明确诊疗关系的复诊可能高度可执行，但不等于初诊可以同样远程化；
- **care-continuity stack / 医疗连续性栈**：复诊、病历、处方、支付、医保、药品配送、线下检查等多环节必须共同连续；
- **multi-channel care redundancy / 多渠道医疗冗余**：成熟数字系统仍保留电话、人工窗口、现场号、亲属代办、基层转诊等 fallback，而不是把所有人强迫进一个 App。

先固定几条边界：

`医院存在 ≠ 本人知道该去哪里`

`专家出诊 ≠ 专家号可获得`

`电话 / 网站可访问 ≠ 预约一定成功`

`预约成功 ≠ 已完成就诊`

`网上咨询 ≠ 互联网诊疗 ≠ 线下初诊的完全替代`

`能线上复诊 ≠ 检查、医保、药品和异常处置都能在线闭合`

`预约比例提高 ≠ 专家供给同比增加`

## 1. Internet 以前：医疗入口首先是地点、时间和科室问题

### 1.1 1986 北京：改善“看病难”首先靠延长门诊、增加医生和专门窗口

1986 年 1 月《人民日报》同期报道北京医疗服务改革时，提到市级医院取消部分下午停诊安排、基层医院实行二十四小时门诊，一些长期难挂的眼科、口腔科情况有所缓和；近二百名高级医师增加挂牌门诊。

来源：

- 1986-01-31《人民日报》同期文本，A/B（当前通过公开历史报纸文本库定位）：<https://cn.govopendata.com/renminribao/1986/1/31/3/>

同一时期北京儿科服务的报刊回顾还能定位到更具体的实体流程调整：1983 年天坛医院为儿科单设挂号窗口，1986 年北京儿童医院调整晚间门诊以应对患儿增加。

来源：

- 《北京日报》历史材料的 2023 年整理，C / institutional-media retrospective：<https://xinwen.bjd.com.cn/content/s655e943ee4b0ec2b81cfa192.html>

这些材料不能证明“1980 年代北京普通患者都容易看病”，也不能证明当时不存在任何电话咨询。它们能证明的是：在大众 Internet 之前，日常医疗可执行性的核心变量已经包括：

- 门诊是否开着；
- 专科窗口是否存在；
- 高年资医生是否真的坐门诊；
- 患者何时到达；
- 科室是否已经满号。

因此互联网后来改变的不是“第一次出现医疗入口”，而是**入口的地址、时间和排队方式**。

### 1.2 1996：电话预约已经可以先于普通 Web 使用

2009 年北京医院预约方式调查回顾，北京大学人民医院从 1996 年已开展电话预约：患者先购买电话预约磁卡并预存款项，再通过固定电话完成预约；北医三院也采用预约卡 + 固话的方式。

来源：

- 北京晚报 / 新浪，2009-08-31，B/C（近时期制度回顾）：<https://news.sina.com.cn/h/2009-08-31/113318547636.shtml>

这个例子非常重要，因为它说明：

> **“离开挂号窗口”不等于“进入 Web”。**

电话、磁卡、预存款和医院后台数据库本身已经可以把部分排队劳动从医院门口搬回家。

但这条路线仍有明确门槛：

`先办卡 → 预存钱 → 有可用固定电话 → 记得预约号码 → 号源仍有余量`。

这与后来“注册账号—绑定身份证—绑定手机—抢网上号”的结构是连续的，而不是两段完全不同的历史。

## 2. 1999–2006：正式联网以后，预约已经存在，但还远没有成为普通就医默认值

### 2.1 1999 北京：电话和 Internet 开始进入统一预约服务，但不能偷换成大众普及

2006 年《人民日报》调查回顾，北京市卫生部门 1999 年开始推动预约挂号卡，覆盖五十多家医院，可通过电话或 Internet 预约；报道同时给出 2004 年北京门急诊约 5035 万人次、预约挂号约 32.5 万人次这一巨大量级差。

来源：

- 人民日报 / 新浪，2006-01-19，B：<https://finance.sina.com.cn/xiaofei/consume/20060119/07102288409.shtml>

这里必须严格分期：

- 1994 年以前：中国尚未完成全功能 Internet 接入时，普通患者的常规就医入口主要仍是医院窗口、电话、单位/基层医疗体系等；
- 1994 年以后：Internet 技术条件存在；
- 1999 年：北京已有面向患者的 Web/电话预约服务；
- 但 2000 年代中期：预约仍只是巨大门诊流量中的很小一部分，不能把“Web 服务存在”写成普通家庭已普遍网上挂号。

### 2.2 2006 第一人称：5 分钟诊疗前可以有 6 小时身体等待

2006 年 1 月的同期报道记录，62 岁的杨女士患严重糖尿病，丈夫长期瘫痪。为了取得北京协和医院专家号，她凌晨 3 点多就到医院排队；6:30 开始挂号，约 8 点取得号，9:30 见到专家，而真正诊疗只有几分钟。她由此直接希望有预约挂号来减少这种等待。

来源：

- 人民日报 / 新浪，2006-01-19，B， contemporaneous first-person embedded in reporting：<https://finance.sina.com.cn/xiaofei/consume/20060119/07102288409.shtml>

这个案例不能代表全国患者，但非常适合证明一种日常时间结构：

```text
medical labor time: minutes
patient access labor: hours
```

预约真正压缩的首先不是医生诊疗本身，而是病人在诊疗前为了“获得被看见的资格”投入的**access labor / 接入劳动**。

## 3. 2005–2012 的扩张型未来：选择入口扩大，但稀缺号源和“挂错科”仍然存在

### 3.1 2009 第一人称：排到第一，也可能因为路由错误重新归零

2009 年《人民日报》报道的李先生为了给儿子看病，坐了两天火车到北京协和医院，又排了一夜队，终于拿到外科第一号；专家听完病情后判断应看风湿科。等他重新回挂号大厅时，风湿科专家号已经全部挂完，只能等下一周。

来源：

- 人民日报 / 新浪，2009-08-20，B， contemporary first-person：<https://news.sina.com.cn/h/2009-08-20/110918475562.shtml>

这里真正缺的不是“更快点击按钮”，而是 **diagnostic-routing support / 诊疗路由支持**：

`我知道要去协和`

并不等于：

`我知道应该挂协和的哪一科`。

所以医疗入口和火车票不同。火车目的地通常由乘客先知道；患者却常常是在专业知识不足的情况下，先自己决定“该买哪张医疗票”。预约系统若只把科室列表搬上网页，就把一部分原本由现场分诊承担的判断劳动转移给了患者。

### 3.2 2009 国家制度化：预约被正式当作减少候诊、连续管理的基础设施

卫生部 2009 年 9 月 30 日正式发布《关于在公立医院施行预约诊疗服务工作的意见》，规定从 11 月起公立三级医院普遍开展预约诊疗，要求定期公布科室、医生专业和出诊时间，提高预约尤其专家门诊比例，推进分时段预约，并要求预约和就诊使用本人有效证件实名办理。

来源：

- 卫生部，2009-09-30，A：<https://www.nhc.gov.cn/bgt/s9514/200909/d5b3893fff4747cdbf91154f5bf109c8.shtml>

这一步把预约从“某家医院的便民功能”推向一种**制度化医疗入口**。

但制度本身没有制造专家时间。武汉同期实名挂号争议材料仍显示，热门专科每天专家号远小于需求。

来源：

- 2009-08 同期报道由财政部网站转载，B：<https://sbs.mof.gov.cn/gongzuodongtai/200908/t20090807_191046.htm>

因此：

`预约覆盖提高` 可以压缩队伍和不确定等待，

但不意味着 `scarce specialist capacity` 同比例增加。

### 3.3 2009 Web 现实：有官网，也不等于官网真有可执行预约入口

北京晚报记者 2009 年 10 月实际逐家体验 49 家三级医院：23 家官网找不到网络预约链接，另有网站打不开或预约链接失效；有些医院把网络预约交给第三方，有的要求先注册并等待管理员回复，有的要求身份证、手机、既往患者 ID/就诊卡，有的甚至使用 email 收集身份与联系方式，再邮件确认预约。

来源：

- 北京晚报 / 凤凰，2009-10-29，B，contemporary service test：<https://news.ifeng.com/mainland/200910/1029_17_1410577.shtml>

所以一条真实链条是：

```text
知道医院名字
→ 找到真官网
→ 找到预约入口
→ 入口仍在线
→ 注册 / 验证身份
→ 具有满足规则的手机或既往就诊卡
→ 选到仍有号的科室
→ 收到明确成功确认
→ 按规定时间到院取号
```

任何一步失败，都可能使“医院支持网上预约”对一个具体人仍然不可执行。

### 3.4 2009 搜索引擎又制造了“入口真实性”问题

同期北京晚报另一项调查发现，患者从搜索引擎搜索“医院 + 网上挂号”时，会进入外观类似官方预约页的第三方/号贩页面；一名患者填到一半才发现 URL 与医院官方公布地址不同。记者还通过页面留下的 QQ、手机号确认部分页面实际由号贩经营。

来源：

- 北京晚报 / 凤凰，2009-11-04，B：<https://news.ifeng.com/society/1/200911/1104_343_1420260.shtml>

这补出 **entry-provenance burden / 入口来源判断负担**：

> 搜索让医疗入口更可发现，也同时要求患者判断“这个看起来像医院的页面，真的是医院吗？”

因此：

`search result visibility ≠ institutional authenticity`。

## 4. 2011–2015：从“每家医院一套入口”走向统一平台，再转向移动端

### 4.1 2011 北京 114：统一的价值首先是把几十套号码、网址压成一个公共地址

北京市卫生部门 2011 年解释建立 114 统一预约挂号平台时，直接指出此前各医院预约方式、电话号码和网址各不相同，不便群众记忆和使用，因此要统一电话和网络入口、统筹号源数据。

来源：

- 北京市卫生局，2011-06-21，A：<https://wjw.beijing.gov.cn/xwzx_20031/wnxw/201912/t20191214_1174492.html>

同年北京妇产医院接入 114 后，初次就诊者不再需要先跑到医院办卡才能电话预约，而可以先在家实名注册、预约，就诊当天再建卡/关联社保卡。

来源：

- 北京妇产医院 / 北京市卫生部门，2011-07-20，A：<https://wjw.beijing.gov.cn/xwzx_20031/jcdt/201912/t20191215_1229292.html>

这可以叫 **address compression / 入口地址压缩**：

`几十家医院 × 各自电话/网址/规则`

部分压成：

`114 / 统一网站 → 医院 → 科室 → 号源`。

但“统一前台”仍不等于后端医疗能力真正统一；号源配额、科室出诊、院内 HIS、就诊卡和现场报到仍然存在。

### 4.2 2014–2015：微信和 App 把入口放进口袋，但认证、绑卡、限时支付又成为新状态

2014 年北京开始出现医院微信预约；同期报道也明确提醒，年轻患者更容易接受，但很多中老年患者并不熟悉微信，窗口仍不能因此消失。

来源：

- 中国广播网 / 人民网，2014-11-25，B：<https://politics.people.com.cn/n/2014/1125/c70731-26089420.html>

2015 年北京儿童医院 App 的同期记者体验已经非常接近后来移动医疗的标准栈：实名信息、患儿与监护人证件、就诊卡绑定、选择科室与时段、10 分钟内支付，否则号源自动释放；紧俏科室即使全部在线开放，一周内也可能只剩一两个号。

来源：

- 新京报 / 人民网，2015-04-07，B：<https://health.people.com.cn/n/2015/0407/c14739-26804767.html>

因此移动化带来的是：

`地点限制 ↓`

同时：

`credential / binding / payment deadline / device literacy dependence ↑`。

## 5. 2015–2019 的拥堵型未来：从“拿到号”继续推进到“哪一部分医疗可以离开医院”

### 5.1 2018 第一人称：复诊可以开始与医院建筑解绑

2018 年《人民日报》记录河南洛阳退休职工王海洋在家通过手机 App 与既往医疗机构医生视频复诊，上传检查单，由医生根据此前诊疗关系和新结果给出复查建议。另一名糖尿病患者刘艳红则从过去每次往返大医院、排队取药，变为到社区完成血糖测试，再和大医院专家视频复诊并取得处方。

来源：

- 《人民日报》，2018-06-22，B，contemporary first-person：<https://society.people.com.cn/n1/2018/0622/c1008-30074364.html>

这里真正发生的是 **care-location decoupling / 医疗地点部分解绑**：

- 医生可以在大医院；
- 患者可以在家或社区；
- 检查结果变成可上传/共享的记录；
- 复诊意见可以通过视频回来。

但它绝不是“从此看病无需医院”。

### 5.2 2018 规则把初诊与复诊明确切开

国家卫生健康委 2018 年印发《互联网诊疗管理办法（试行）》等文件，互联网诊疗的制度边界明确围绕部分常见病、慢性病复诊以及已经能够获得患者病历资料的情形展开。

来源：

- 国家卫生健康委，2018-09-14，A：<https://www.nhc.gov.cn/yzygj/c100068/201809/d53877b9685d4e7ca991f77542402c1b.shtml>
- 同期政策解读，A：<https://www.nhc.gov.cn/yzygj/c100067/201809/f1f660ad9ade4b01ac759b3e0e88e019.shtml>

《人民日报》同期解释也非常直接：线上医疗可以对稳定的常见病、慢性病复诊、调药等发挥作用，但初次诊断仍需要体格检查、检验、影像等线下能力。

因此必须固定：

`online care availability ≠ first-visit substitutability`。

这条区分能防止后来把“互联网医院”写成一种无差别替代实体医院的技术神话。

## 6. 2020–2022 的偶发型未来：远程医疗从便利层变成连续性 fallback

### 6.1 2020 武汉：慢病患者无法出门时，复诊—处方—配送链真正成为生活连续性设施

武汉市第一医院互联网医院 2020 年 3 月 1 日上线；湖北省卫健委转载的同期报道记录，首日访问量超过 1.1 万。患慢性荨麻疹多年的李先生原本几乎每月到院复诊配药，疫情期间无法出门、药将吃完，于是通过线上问诊取得医生回复，并使用药品配送到家。

来源：

- 湖北省卫生健康委员会 / 荆楚网，2020-03-09，A/B，contemporary first-person：<https://wjw.hubei.gov.cn/bmdt/ztzl/fkxxgzbdgrfyyq/fkdt/202003/t20200323_2188001.shtml>

这个案例适合写成一条完整的 **care-continuity stack**：

```text
prior diagnosis
→ remote authentication
→ doctor reachable
→ consultation
→ electronic prescription
→ payment / platform state
→ pharmacy fulfilment
→ delivery
→ medicine physically reaches patient
```

任何一层断掉，“线上有医生”仍不足以维持治疗连续性。

### 6.2 疫情没有创造远程医疗，它把已有能力从 optional 变成 fallback

2018 年已有明确互联网诊疗制度和实例；2020 年危机改变的是**执行必要性**。当线下移动突然受限时，先前主要被理解为便民的远程复诊、续方和配送，开始承担“如果这条链断掉，慢病治疗会直接中断”的基础设施角色。

因此这里不能写：

`COVID → 发明互联网医院`。

更准确的是：

`既有远程能力 → 危机强制压力测试 → 一部分流程被证明可承担连续性`。

## 7. 2023–2026 的防守型未来：成熟方向不是“全部线上”，而是给失败准备多条 fallback

### 7.1 2023 同时代第一人称：线上就诊已进入日常，但担忧也从“有没有”转向“屏幕后面是谁”

《中国青年报》2023 年调查中，80 后母亲唐菲回忆第一次线上问诊是在孩子夜间发烧、医院较远时；此后在紧急但未必需要立刻线下急诊的情形中，她会把线上咨询作为一种入口。该调查的 1508 人网络样本中，63.2% 称体验过线上就诊，但这种网络样本不能外推全国人口。

来源：

- 《中国青年报》，2023-03-16，B，contemporary first-person + nonrepresentative survey：<https://zqb.cyol.com/html/2023-03/16/nw.D110000zgqnb_20230316_4-10.htm>

同一调查里，受访者对医生资质和平台信息准确性仍有明显担心。这说明当“能打开线上问诊”逐渐普通以后，**provenance / qualification verification** 又成为新的执行条件。

### 7.2 2024 湖北：给老年人保留现场号、代预约和人工窗口，是数字系统成熟而不是倒退

湖北省 2024 年便利老年人就医措施要求建设统一预约平台，同时明确：

- 部省属医院向市县医疗机构预留不低于 10% 的门诊号源用于转诊；
- 医联体/医共体牵头机构向基层预留不低于 20%；
- 畅通家人、亲友、家庭签约医生代预约；
- 保留一定比例现场号源；
- 保留人工窗口，并推进长辈模式、陪诊/云陪诊等支持。

来源：

- 湖北省卫生健康委、湖北省医保局，2024-09-05/09-13 发布，A：<https://wjw.hubei.gov.cn/zfxxgk/zc/gkwj/ybxwj/202409/t20240913_5336196.shtml>

这是一种非常典型的 **multi-channel care redundancy / 多渠道医疗冗余**：

```text
统一在线平台
+ 电话 / 人工窗口
+ 现场号源
+ 家属代办
+ 家庭医生 / 基层转诊
+ 适老界面
```

真正防守型的基础设施不是“所有人必须会用最新入口”，而是**一个入口失败时仍有别的路线。**

### 7.3 2025 反例：线上“前方 0 人”等待，也不等于医生此刻真正可接诊

2025 年上海媒体接到多名患者反映，互联网医院已经显示预约和队列状态，却仍出现医生未按预期时间接诊、患者在线等待数小时的情况。68 岁患者叶女士为了避免往返约两小时，预约线上门诊，界面显示前方无人，但医生迟迟未接诊。

来源：

- 解放日报/上观新闻经人民网，2025-08-11，B，contemporary first-person：<https://sh.people.com.cn/n2/2025/0811/c350122-41318929.html>

这补出新的边界：

`virtual queue state ≠ clinician actually available now`。

二十年前的“窗口开着但专家号已没”并没有被彻底消灭；它只是可能变成“界面显示在线、队列为零，但真正的医生时间仍被线下门诊和其他任务占用”。

### 7.4 2025 的规模说明它已经是基础设施，但规模不能直接证明每个流程可靠

国家卫生健康委在 2025 年发布的统计显示，87% 的二级以上公立医院已开展预约诊疗服务，全国互联网医院达到 3756 所；2024 年互联网医院诊疗人次约 1.3 亿。

来源：

- 国家卫生健康委发布会经人民网，2025-09-11，A/B：<https://health.people.com.cn/n1/2025/0911/c14739-40561867.html>

这些数字足以证明预约/互联网医院早已不是少数试验，但不能从“1.3 亿诊疗人次”跳到：

- 每个普通人都能熟练使用；
- 每次线上问诊都比线下更快；
- 医疗资源地区差异已经消失；
- 专家稀缺已经解决。

## 8. 海外对照：Web 以前已经存在数字健康服务，但“数字化哪一层”差异很大

### 8.1 1986–1989 法国 Minitel：医生网络、患者信息与真正诊疗必须分开

法国 Minitel 是很好的前 Web 对照，但不能把所有“医疗 + Minitel”都叫远程看病。

1989 年发表的医学信息学论文记录：法国阿基坦从 1986 年 10 月开始，让约占当地全科医生 5% 的 sentinel GP 网络通过家中的 Minitel 终端和电话线向波尔多大学医学中心提交流行病学病例数据。

来源：

- Maurice, Salamon & Dabis, 1989，A/B scholarly report of contemporary system：<https://pubmed.ncbi.nlm.nih.gov/2622292/>

这证明的是 **professional health telematics**，不是普通患者在家看医生。

1987 年《世界报》同期报道 Chambéry 的 Crystel / SANTAL Minitel 服务，为血友病患者和公众提供疾病、预防、研究状态和专科中心地址等信息，并与家庭自我治疗背景相关。

来源：

- *Le Monde*, 1987-03-26，A/B contemporaneous reporting：<https://www.lemonde.fr/archives/article/1987/03/26/la-sante-par-l-ecran-le-service-telematique-de-chambery-permet-aux-hemophiles-de-traiter-a-domicile-leur-maladie_4052128_1819218.html>

1988 年法国已有 337 万余台 Minitel，France Télécom 数据称可接触终端的人口比例已相当可观。

来源：

- *Le Monde*, 1988-04-21，B / contemporaneous infrastructure report：<https://www.lemonde.fr/archives/article/1988/04/21/reflux-des-messageries-hausse-des-services-professionnels-le-deuxieme-souffle-du-minitel_4102726_1819218.html>

因此跨国比较最重要的不是“谁更早有网上医疗”，而是把层级拆开：

```text
health information
≠ professional data network
≠ symptom triage
≠ appointment booking
≠ doctor-patient consultation
≠ prescription
≠ physical examination / procedure
```

中国 2000s–2020s 的历史同样必须沿这条层级拆，而不能把“医院网站”“网上挂号”“健康咨询”“互联网医院”统统压成一个词。

## 9. 四种未来的比较

| 时段 | 更典型的新增能力 | 新的/仍在的约束 | 时间感 |
|---|---|---|---|
| 2005–2012 扩张型未来 | 电话/Web 预约、实名预约、统一平台开始形成 | 专家稀缺、科室判断、入口真假、碎片化网址、外地患者到院成本 | “以后应该不用再凌晨排队，可以提前计划” |
| 2015–2019 拥堵型未来 | 手机 App/微信、绑卡、移动支付、互联网复诊 | 抢号转成放号/支付时点竞争；初诊仍需线下；数据和资质验证增加 | “流程能继续压缩，但优质医生时间还是有限” |
| 2020–2022 偶发型未来 | 远程复诊、续方、配送在危机中承担 continuity | 需要既往病历、平台可用、医生在线、物流/支付闭环 | “原来正常去医院这件事也可能突然无法执行” |
| 2023–2026 防守型未来 | 线上线下一体、统一预约、代预约、基层转诊、适老 fallback | 数字排队仍可等待；老年/设备/认证鸿沟；专家容量仍有限 | “好的系统不是只有一条最先进路线，而是失败时仍能看上病” |

这四种时间感不是全国统一心理状态，而是分析同时代制度、平台与第一人称材料时的工作模型。

## 10. 它改变了“普通人到底有多少种活法”的哪一点？

医疗可执行性会直接改变一个人能不能维持其他人生路线。

一个慢病患者如果每月复诊都需要：

`请一天假 + 长途交通 + 凌晨排队 + 取药`

那么工作地点、迁居距离、照护安排和可支配时间都会被这条医疗链约束。

当部分复诊变成：

`在家/社区复查 → 在线复诊 → 电子处方 → 药品到家`

一个人就可能在不切断原医疗关系的情况下住得更远、继续工作或减少照护者陪同。

但同样重要的是反例：

- 初诊和急危重症不会因为 App 存在而自动远程化；
- 专家时间仍稀缺；
- 老年人可能需要代理；
- 网络入口也可能坏、假、忙或无人接诊。

所以真正增加生活自由度的，不是“医疗上网”这四个字，而是：

> **一个人的身体出问题以后，她是否有不止一种可靠路线，把自己重新接回真实医疗系统。**

## 11. 证据等级与后见之明风险

### 已证实

- 1980s 北京已经通过门诊开放时间、专科窗口、增加医生等方式处理实体就医可达性问题；
- 1996 年北京至少部分医院已有电话预约卡模式；
- 1999 年北京已存在电话/Internet 预约服务；
- 2006–2009 同期患者材料明确记录凌晨排队、跨省交通、挂错科后重新排队等接入劳动；
- 2009 年预约诊疗被国家层面制度化推进；
- 2009 年医院网站的网络预约入口高度碎片化，并存在第三方、失效链接和伪官方页面；
- 2011 年北京统一 114 平台明确以统一电话、网址和号源数据为目标；
- 2018 年互联网诊疗制度明确存在初诊/复诊边界；
- 2020 年互联网医院在疫情条件下实际承担慢病复诊、续方和配送；
- 2024 年至少湖北政策明确要求在数字预约之外保留代预约、现场号、人工窗口等 fallback；
- 2025 年互联网医院已达到大规模使用，同时仍存在虚拟等待与医生实际可达性不一致的个案。

### 可以合理推断，但不应写成普遍事实

- 预约制度把部分患者等待从医院物理队列迁移到电话、网页和放号时点；
- 远程复诊可以降低一部分慢病患者维持异地工作/居住时的医疗连续性成本；
- 统一平台降低了记忆和判断多个医院入口的成本；
- 多渠道 fallback 是成熟数字医疗对年龄、设备和故障差异的一种适应。

### 不能推断

- 1999 年有网上预约，所以普通家庭当时已经普遍网上挂号；
- 预约率上升，所以专家资源短缺已经解决；
- 互联网医院规模增长，所以线下医院会被替代；
- 某一名患者省了数小时，所以所有线上复诊都更快；
- 老年人保留人工窗口，说明数字化“失败”或“不先进”。

### 主要后见之明风险

1. **把 2020 当起点**：中国互联网医疗和远程医疗在疫情前已经存在；
2. **把 Web 当成第一个远程入口**：电话预约先于普通 Web 大众使用；
3. **把挂号当成医疗本身**：取到号只是就医链最前端；
4. **把可见号源当成新增资源**：数字系统主要重新配置发现、分配和排队；
5. **把线上问诊当成无条件初诊**：2018 后的正式制度对初诊/复诊有明确边界；
6. **把“年轻人会用 App”投射为所有人**：老年人、儿童、无智能设备者、异地患者的执行条件不同。

## 12. 还不知道什么

1. 1980s–1990s 中国不同地区普通医院的挂号窗口、电话咨询、单位转诊和基层转诊在日常中究竟如何组合，仍缺更系统的同时代患者材料；
2. 1999 北京早期预约挂号卡的原始 Web 界面、浏览器/编码、后台协议和真实日活使用结构尚未恢复；
3. 2009 年各医院官网的预约页面，哪些历史 capture 仍可在 Wayback / Common Crawl 中验证，尚需 old-web companion 继续做 M1 级复原；
4. 预约制对外地患者的住宿夜数、误工时间、陪护时间究竟减少多少，缺长期可比数据；
5. 网上导诊是否真正降低“挂错科”比例，当前材料不足；
6. 互联网医院在复诊之外，对检查、影像、病理、手术和急症的不可远程部分怎样重新安排到线下，仍应逐病种拆；
7. 老年人由家属代预约时，究竟减少了患者劳动还是把数字行政劳动转移给成年子女，需要家庭时间研究；
8. 2025–2026 互联网医院医生的线上时段是否变成额外劳动、碎片劳动或与线下门诊竞争，值得单列医生端时间史。
