# 从“必须回到墓前”到“给逝者一个持续可访问的地址”：网上纪念、远程祭扫与死后记忆连续性（中国，2000—2026）

> 研究切口：亲人去世以后，普通人的生活并没有停止。谁通知远方亲友，谁去墓地，谁维护墓位，无法返乡时怎样表达哀思，几年以后还能不能继续“对逝者说话”，以及照片、文字和家庭记忆到底由谁长期保管，都会成为新的生活事务。
>
> 本文不是殡葬制度通史，也不评价哪一种祭祀方式“更文明”或“更真诚”。研究问题是：**通信与互联网基础设施怎样改变哀悼、祭扫和家庭记忆的可执行边界，同时又制造哪些新的平台依赖、身份核验和保存风险。**
>
> 检索日期：2026-09-08。

## 1. 为什么死亡仍然是 life-history 问题

一个人的死亡是其本人生命历程的终点，却会立即成为幸存者生活史中的新事务。

对一个普通家庭来说，至少可能出现这些长期任务：

- 通知亲属、朋友、同事；
- 奔丧、请假、买票、跨城或跨国移动；
- 葬礼、火化、安葬与墓位事务；
- 清明、忌日、生日等周期性纪念；
- 墓碑清洁、献花等物理维护；
- 保管照片、录像、书信、遗物和生平材料；
- 向下一代解释“这个人是谁”；
- 在新的家庭事件发生时继续向逝者“汇报”；
- 决定死者留下的数字账号、照片、游戏账号或其他数据以后怎么办。

因此死亡以后，家庭常常同时受到几只钟控制：

1. **ritual clock / 仪式时钟**：葬礼、清明、忌日等什么时候发生；
2. **mobility clock / 移动时钟**：在外工作、上学的人能不能及时回来；
3. **kinship clock / 亲属时钟**：家人怎样判断“尽到心意”与“没有回来”；
4. **memory clock / 记忆时钟**：照片、故事和细节多久以后开始消失；
5. **platform clock / 平台时钟**：网站、域名、账号和商业公司究竟能活多久；
6. **legal-administrative clock / 法律与行政时钟**：死亡事实、遗产、账号和数据什么时候被制度承认并允许处理。

本轮新增六个分析变量：

- **ritual-location decoupling / 仪式—地点解耦**：纪念是否必须和身体到墓地绑定；
- **continuing-bond address / 持续关系地址**：逝者是否拥有一个可以多年反复访问、留言、添加家庭新消息的数字地址；
- **mourning proxy stack / 追思代理栈**：无法本人到场时，网络、墓园工作人员、亲友、视频分别替代哪一段动作；
- **public-mourning/private-kin gap / 公共悼念—私人亲属缺口**：一个人接受网上纪念公共人物，不等于接受它替代亲人墓前祭扫；
- **perpetuity-contract gap / 永久想象—平台寿命缺口**：用户希望纪念“永久”，平台却只是一个需要域名、服务器、维护和商业持续性的服务；
- **posthumous-memory governance / 死后记忆治理**：生前的人是否开始主动决定自己死后哪些数字痕迹保留、删除或交给谁。

核心状态不能简化成 `ONLINE_MEMORIAL = MOURNING COMPLETED`：

```text
亲人死亡
→ 死亡事实被家属知道
→ 亲友被通知
→ 是否存在物理墓位/骨灰安放地
→ 家属能否亲自到场
→ 若不能到场，是否有远程替代通道
→ 网上纪念页是否建立
→ 页面是否准确对应真实逝者
→ 亲属是否认可这一纪念方式
→ 其他亲友是否能访问
→ 留言/照片/祭品是否真正保存
→ 多年后页面是否仍可访问
→ 平台关闭时是否可导出
→ 下一代是否还能理解这些材料
```

因此：

- `memorial page exists != death verified`
- `page reachable != kinship acceptance`
- `virtual flower sent != physical grave maintained`
- `online ritual available != family accepts substitution`
- `platform promises permanence != platform survives`
- `public archive capture != private grief preserved`

## 2. Internet 以前：远程哀悼并不是从零开始，但“墓地”仍然高度地点化

本轮没有把 1994 年以前的中国普通家庭写成“没有远程通信”。死亡通知、不能返乡时的问候与哀悼，本来就可以经由书信、邮政、电报、电话、报刊讣告以及亲友转告发生；墓祭、墓碑维护和许多家庭仪式则仍然高度依赖某个具体地点以及能到达那个地点的人。

这一前史目前还缺一组足够扎实的中国普通家庭同期个人材料，所以本文只把它作为边界，不把某一种通知方式写成全国普遍流程。

### 2.1 海外 pre-Web 对照：Internet 继承了报刊、广播和电视的“死亡通知”功能

加拿大的 World Wide Cemetery 现存页面保存了创办者 Mike Kibbee 标注为 1995 年 4 月的原始构想。他当时明确把 Web 放在已有媒介之后：人们此前会使用印刷品、广播和电视通知他人死亡，而 Web 可以把讣告/纪念扩展成一个全球可访问、可放照片、声音和家庭链接的长期页面。

- World Wide Cemetery, *The Classic Design 1995–2014 / Mike’s original 1995 vision*: https://cemetery.org/20-years-word-wide-cemetery-classic-design/
- 证据：C/A boundary（站点当前保存并声称为 1995 原始文本；本轮未取得独立 1995 capture），confidence: medium-high for the site’s own historical claim。

World Wide Cemetery 当前站点仍称其创建于 1995 年，并自称是最早持续运行的网上墓园之一。

- https://cemetery.org/
- 证据：C/current observable claim，confidence: medium。

这条海外线最重要的比较不是“谁第一”，而是共同机制：

> **Internet 没有发明死亡通知和纪念，而是第一次让普通家庭可以把一份纪念材料变成一个可反复访问的 URL。**

## 3. 2001—2004：中文旧网上已经出现“给逝者建一个页面”，但存在不等于普通人接受

### 3.1 2001 年已经存在相当多样的中文“虚拟墓地”产品

2001-03-26《北京晚报》经新浪科技保存的同期资料，列出了当时多家提供网上纪念/虚拟墓地的站点，并留下非常有价值的 historical locators：

```text
网同纪念            http://cn.netor.com
华夏宇宙祭奠园      http://www.7054321.com/
清明网              http://www.qingming.com.cn
地球村网上公墓      http://www.ev991.com
中华清明网          http://www.qingming.net/
英特公墓            http://www.inter-cemetery.com
```

报道描述的功能已经包括：在线建馆、在线纪念、照片保存、网上讣告、论坛/茶室、鲜花与其他虚拟纪念动作。

- 新浪科技转载《北京晚报》，2001-03-26，《国内提供开设虚拟墓地服务网站一览》：https://tech.sina.com.cn/i/c/59673.shtml
- 证据：B（同时代媒体产品清单），confidence: high for the listed locators/features, not for user adoption。

2002 年中新社报道再次直接写出 Netor 的 historical host `CN.NETOR.COM`，并描述记者实际进入用户自建园区、看到留言与虚拟鲜花、烛光、歌曲等功能。

- 新浪转载中新社，2002-04-04，《传统清明节即将到来 中国网络祭祀忙碌不堪》：https://news.sina.com.cn/s/2002-04-04/0605534052.html
- 证据：B（同时代记者观察 + 平台方规模自报），confidence: high for host/function existence; low-medium for traffic claims。

由此可以确认：到 2001—2002 年，中文 Web 已经具备一个完整的“持续关系地址”雏形：

```text
逝者姓名/照片
+ 生平文字
+ 一个 URL
+ 亲友访问
+ 留言
+ 虚拟献花/点烛/音乐
```

但这只能证明 `available`，不能证明 `normal`。

### 3.2 2004 嘉定：普通家庭确实已经有人把父亲的纪念堂当作持续入口

2004 年《嘉定报》同期报道了一个非常具体的普通人案例：安亭镇某企业陈先生当年 1 月在网同纪念的福寿园园区给已故父亲建立“纪念堂”。记者随后实际打开网页，看到父亲照片、姓名、生辰、简历，以及“纪念文选”“历史相册”“活动年谱”等栏目；两个月里亲友访问并送歌、鲜花和虚拟酒。

- 《嘉定报》，2004-03-30，相关清明报道数字版：https://mobile.epaper.routeryun.com/index.php/home/article/index/appkey/49/date/2004-03-30/page/34986/aid/212430.html
- 证据：B（同时代地方媒体记者观察普通家庭案例），confidence: high for the described use case。

这已经不是“平台宣传有人会这样用”，而是一个现实生活链：

```text
父亲死亡
→ 儿子建立纪念页
→ 亲友知道 URL
→ 分散亲友反复访问
→ 家庭材料逐渐堆积成一个可持续入口
```

### 3.3 同年重庆反例：功能已经完整，普通家庭仍可能几乎不用

2004 年重庆晚报的同期调查给出了非常必要的 adoption 反证：南山龙园此前一年开了网上纪念业务，安放骨灰 4000 余具，却只有 12 名普通人建立网络纪念馆；江南殡仪馆 2001 年即上线相关服务，却因无人响应最终取消。报道同时描述在线献花、点歌、点烛、上香、祭酒、留言板和历史相册等功能都已经存在。

- 搜狐转载《重庆晚报》，2004-03-25，《网上祭奠少人问津》：https://news.sohu.com/2004/03/25/99/news219599967.shtml
- 证据：B（同期地方调查），confidence: high for these institutions’ observed low uptake。

这给本专题留下一个最重要的 adoption rule：

> **功能完整 ≠ 文化上可替代 ≠ 家庭实际采用。**

同一个 2004 年，中国不同城市、不同家庭就已经可以同时存在“经常上网纪念父亲”和“几乎没人愿意用”的两种生活。

## 4. 2005—2012：扩张型未来里，逝者第一次可以拥有一个“不会因为朋友住得远而关闭”的地址

### 4.1 2008 广州：网络纪念把去世妹妹重新接回外地同学和朋友

2008-04-09《南都周刊》的一份同期人物材料，是本轮最重要的 2007—2010 第一人称锚点。

27 岁的广州人林良英，一年前失去因癌症去世的妹妹。他付费建立网上纪念馆，直接目的就是让外地同学和朋友也能方便纪念。妹妹去世后的第一个清明，网站切换清明版式，亲友在纪念馆献歌、点烛、留言。林把这里描述成自己在网络世界中少数/唯一使用真名的地方。

- 新浪转载《南都周刊》，2008-04-09，《虚拟祭祖：市场经济进驻虚拟墓地》：https://news.sina.com.cn/c/2008-04-09/164415322655.shtml
- 证据：B（同期记者人物采访），confidence: high for Lin’s experience; platform-scale figures in the same article remain company/media claims。

这里出现了 **ritual-location decoupling**：

```text
妹妹的遗骸/墓地在一个地点
朋友和同学散在多个地点
↓
共同纪念不再要求所有人同日回到同一个墓前
```

它并没有取消墓地，却把“谁能参加纪念”的地理半径扩大了。

### 4.2 这也是一种“持续关系地址”

同一报道描述，Netor 当时允许用户用逝者姓名建立纪念馆，并提供点烛、献花、纪念文章等持续功能。平台把自己理解成一种超越时空的纪念补充，而不是物理墓葬替代品。

这使逝者第一次可以拥有一种接近“地址”的东西：

- 今天可以访问；
- 明年清明仍可访问；
- 远方亲友拿到 URL 也可以进入；
- 新的照片、文章、家庭消息可以继续堆上去。

与纸质相册不同，这个地址既是档案，也是行动界面。

### 4.3 反例：2008 年的人已经非常清楚“网页可能死得比纪念对象更早”

2008-04-07《中国青年报》的调查极其重要，因为它防止我们把早期网上纪念写成天真乐观的“数字永生”。

记者观察到：

- 多家网站对建馆、维护和虚拟祭品收费；
- 一些套餐把 5 年、10 年、20 年维护期直接商品化；
- 一家早期免费网上公墓到 2008 年已经几近瘫痪，搜索失效、内容多年不更新；
- 受访消费者明确担心：付费以后如果网页突然消失，该去找谁；
- 一名初三学生原本想因学业不能扫墓而试网上祭扫，但家庭最终因为长期服务是否可靠而犹豫。

- 中国青年报，2008-04-07，《网上祭扫：说起来容易做起来难》：https://zqb.cyol.com/content/2008-04/07/content_2132646.htm
- 证据：A/B（同期报刊调查与消费者自述），confidence: high。

这里新增 **perpetuity-contract gap / 永久想象—平台寿命缺口**：

```text
我希望纪念父亲几十年
!= 我购买的是一个几十年必然履行的可靠服务
!= 域名几十年存在
!= 数据几十年完整
!= 账号密码几十年可找回
```

这意味着“扩张型未来”也不是无条件信任。2008 年普通消费者已经能意识到：**把永久记忆交给一个网站，本身就是一种长期风险。**

## 5. 网上纪念没有自动取代扫墓：它更像给迁移家庭增加了一条备用路径

网上祭扫最容易被误写成“年轻人不回家了”。现有证据恰好说明，更常见的是**补充、替代失败后的 fallback、或不同亲属之间并存**。

### 5.1 2017：常年在国外的人可以持续参加，但“距离远”仍是前提之一

2017 年《光明日报》报道，网友“灵犀”一家因常年定居国外，清明难以返乡，两年前开始为去世亲人建立网上纪念馆。家人会在清明打开网页，上香、点烛、献花、留言。

- 人民网转载《光明日报》，2017-04-04，《在网上，为逝去的亲人写封信》：https://media.people.com.cn/n1/2017/0404/c40606-29187628.html
- 证据：B（同期媒体人物材料），confidence: medium-high。

这更适合解释为：

> **迁移距离越大，网上纪念作为“至少还能参加”的通道越有价值。**

不能反推没有迁移障碍的家庭也同样愿意放弃墓前仪式。

### 5.2 2015 年“代客扫墓”进一步证明：网络能协调仪式，但不能替身体擦墓碑

2015 年河北/全国网店调查显示，部分网店已经通过网络接受代客扫墓订单：工作人员现实中寻找墓位、擦碑、献花、鞠躬，录制视频，再把结果发给远方委托人。同期店主又明确说，大量店铺业务量很低，说明存在仍不等于普遍接受。

- 人民网转载《燕赵晚报》，2015-04-03，《网店清明节推“代客扫墓”》：https://culture.people.com.cn/n/2015/0403/c172318-26795505.html
- 证据：B（同期记者调查），confidence: high for workflow, low for broad prevalence。

于是出现 **mourning proxy stack**：

```text
远方家属
→ Web/QQ/电话下单
→ 本地工作人员收到墓位和需求
→ 工作人员身体到墓地
→ 擦碑/献花/行礼
→ 摄像
→ 视频回传
→ 家属确认
```

这里 Internet 没有“虚拟化”墓碑维护，而是**把别人的身体调度到墓前**。

## 6. 2015—2019：拥堵型未来不是“不在乎故乡”，而是人生项目开始互相撞日历

### 6.1 2019 南京大学生：学校日历与返乡祭扫发生冲突

2019-04-01《南京日报》材料记录，在南京仙林大学城上学的马灿灿因清明无法赶回宁夏固原，为爷爷奶奶建立网上纪念堂，并把链接发给亲友，亲友通过送花、鞠躬等按钮参与。

- 中国江苏网转载《南京日报》，2019-04-01：《心语亭对话，墓园办诗会，网上“云祭扫”——今年清明，“低碳”祭扫成时尚》：https://jsnews.jschina.com.cn/hxms/201904/t20190401_2277497.shtml
- 证据：B（同期记者人物材料），confidence: high for this case。

这个例子不能写成“2019 大学生开始不回家扫墓”。更准确的是：

```text
大学教育在南京
家庭墓地在宁夏固原
清明只有有限时间
↓
互联网提供一个不会要求先解决长距离交通的参与方式
```

这属于 **calendar congestion / 日历拥堵**：教育、工作、迁移和家庭仪式都是真实义务，但它们不再天然发生在同一个地点、同一套时间表里。

### 6.2 同期现场人数仍然庞大：online 并没有替代 offline

同一南京报道开头还记录，清明扫墓高峰约有 73 万市民前往当地墓园。

因此 2019 的正确状态不是：

`physical grave -> online memorial` 单向替代，

而是：

`physical visit + online memorial + remote family link + other local rituals` 并存。

## 7. 2020—2022：偶发型未来把“备用祭扫路径”突然变成基础设施

疫情最重要的影响不是发明云祭扫，而是把原本可选的远程方式，在短时间里变成许多家庭唯一仍可执行的路径。

### 7.1 2020：以往每年返乡的人第一次不得不在网上完成家庭追思

2020 年央广网采访河南商丘市民刘茜。她已在广州工作多年，以往清明都会专门从广州返乡给父亲扫墓；当年因为疫情，她改为给父亲建立网上纪念馆，和家人一起线上追思。

- 央广网，2020-04-05，《全国多地推出线上“云祭扫”》：https://china.cnr.cn/yaowen/20200405/t20200405_525042795.shtml
- 证据：A/B（同期记者采访），confidence: high。

这是一条非常干净的 before/after：

```text
过去：广州工作 → 清明返河南 → 墓前祭扫
2020：广州工作 → 跨省移动路径不可用 → 网上纪念 + 家庭追思
```

因此新增 **ritual continuity under mobility shock / 移动冲击下的仪式连续性**。

### 7.2 “云祭扫”和“代祭扫”不是同一件事

2020 年陕西的同期报道显示，墓园同时提供：

- 网络纪念馆、虚拟祭品、在线留言；
- 工作人员实际擦拭墓碑、献花、代读家属信件；
- 通过照片/视频把完成情况反馈给家属。

- 人民网转载《陕西日报》，2020-03-31，《“代客祭扫”“云祭扫”传达追思之情》：https://sn.people.com.cn/n2/2020/0331/c378288-33915443.html
- 证据：A/B（同期地方报纸与现场服务），confidence: high for service distinction。

这必须拆成两种不同事务：

```text
A. ONLINE SYMBOLIC RITUAL
用户 -> 页面 -> 虚拟花/烛/留言

B. REMOTE PHYSICAL PROXY
用户 -> 委托 -> 墓园工作人员 -> 现实墓位 -> 清洁/献花 -> 影像回传
```

B 仍然依赖一个真实的人、一条可以进入墓区的路和一个能定位的墓位。

### 7.3 2022：网络祭扫规模暴增，但这更像 crisis-induced substitution，不能倒推长期偏好

民政部统计显示，2022 年清明三天累计现场祭扫约 1754 万人次，网络祭扫约 2156 万人次，网络祭扫同比增长 192%；4 月 5 日当天各地有 1523 个网络祭扫平台。

- 新华社，2022-04-05：https://www.news.cn/2022-04/05/c_1128533790.htm
- 证据：A（民政部统计经新华社发布），confidence: high for reported counts。

但当时恰逢多地疫情防控限制。最重要的 hindsight risk 是：

> **2022 网络祭扫人数超过现场祭扫，不能写成中国家庭已经总体偏好网上祭扫。**

它更直接证明的是：当现场路径被大规模限制时，备用数字通道可以突然承载极高流量。

## 8. 2023—2026：防守型未来开始延伸到“我死后自己的数字生活怎么办”

这里必须避免把年轻人写成“更悲观、更怕死”。更准确的新变化是：数字生活累积得足够多以后，**身后可控制性本身开始成为可以提前规划的事务**。

### 8.1 2023 年同期第一人称：年轻人开始主动选择“保留 / 删除 / 部分保留”

2023 年《北京青年报》采访一组 Z 世代年轻人，讨论死亡后社交账号、照片、视频、游戏等数字痕迹。报道明确把受访者分成“保留派、删除派、部分保留派”。受访者“木南”认为可以保留一部分信息，但涉及私人图片、视频的内容应谨慎处理。

- 中新网转载《北京青年报》，2023-04-07，《“数字永生”，一些Z世代开始给“电子遗物”立遗嘱》：https://www.chinanews.com.cn/sh/2023/04-07/9985529.shtml
- 证据：B（同期专题采访），confidence: high for existence of different preferences, not population shares。

新增 **posthumous privacy preference / 死后隐私偏好**：

```text
我希望家人记得我
!= 我希望家人得到我的全部聊天记录/照片/视频
```

数字记忆保存因此第一次同时包含“别丢”和“别全留下”两种相反的生活目标。

### 8.2 2025 年反例：建立“纪念馆”甚至不能自动证明这个人已经死亡

2025 年法治报道重新调查网络祭祀平台时引用厦门思明区法院案件：某平台未核验逝者信息，导致一名仍在世女性的照片和个人资料被拿去创建纪念馆，并持续存在多年。记者随后测试的一些平台也存在创建纪念馆时资料核验非常弱的问题。

- 中新网转载《法治日报》，2025-04-05，《荒唐！网络平台惊现活人被祭奠、香火排行榜？》：https://www.chinanews.com.cn/sh/2025/04-05/10394959.shtml
- 证据：B/A boundary（法院案例经法治媒体报道 + 记者平台测试），confidence: high for the reported failure mode。

于是 old-Web 以来一直被忽略的一个状态必须正式出现：

```text
MEMORIAL_CREATED
!= DECEASED_IDENTITY_VERIFIED
!= DEATH_FACT_VERIFIED
!= FAMILY_AUTHORIZED
```

页面越容易建立，就越需要新的身份治理。

### 8.3 2026：22 岁的人已经会把多年游戏账号写进遗嘱

2026 年《中国青年报》依据中华遗嘱库 2025 年度白皮书报道，一名 22 岁受访/案例对象把银行存款和使用 7 年的游戏账号一起写入遗嘱。白皮书还显示 30 岁以下立遗嘱者数量继续增长。

- 中国青年报经北京日报转载，2026-03-22：https://news.bjd.com.cn/2026/03/22/11644676.shtml
- 证据：B（机构白皮书典型案例经媒体报道），confidence: high for case existence, not population-wide norm。

这里的“防守”不是“不敢生活”，而是：

> **我活着的时候已经积累了一个足够厚的数字自我，所以希望意外发生时，它不要完全按照平台默认规则处理。**

### 8.4 2026 清明又给了一个重要 denominator：网络祭扫仍远没有取代身体到场

民政部 2026-04-04 数据：清明假期首日，全国现场祭扫约 1928.93 万人次；857 个网络祭扫平台服务网络祭扫约 26.62 万人次。

- 中国新闻网，2026-04-04：https://www.chinanews.com.cn/sh/2026/04-04/10598846.shtml
- 证据：A（民政部统计经中新网发布），confidence: high。

这与 2022 疫情高峰形成非常有价值的反向校验：

```text
2022 physical route restricted -> network volume can exceed onsite
2026 physical route open       -> onsite remains overwhelmingly larger on peak day
```

因此“云祭扫已经替代传统祭扫”是明显错误的线性故事。

## 9. 跨国比较：1995 年网上墓园与后来社交网络都出现了同一个机制——让“对死者说话”变成公共/半公共持续活动

World Wide Cemetery 的 1995 原始构想已经把 Web memorial 想成传统讣告、石碑之外的长期页面。到 2010 年，Carroll 与 Landry 对 MySpace、Facebook 等社交网络哀悼的研究又观察到：原本非常私人的“给死者留言”，会在网络社交空间中变成可被他人看到、回应和共同参与的活动。

- Brian Carroll & Katie Landry, 2010, *Logging On and Letting Out: Using Online Social Networks to Grieve and to Mourn*: https://journals.sagepub.com/doi/10.1177/0270467610380006
- 证据：学术二手/同期研究，confidence: high for the studied cases, not universal behavior。

2011 年一项对 20 个 SIDS 丧子母亲纪念网站的研究，则在页面、叙事、留言簿和社群关系中发现持续的身份建构与社区联系。

- PubMed: https://pubmed.ncbi.nlm.nih.gov/21748920/
- 证据：peer-reviewed study，confidence: high for sample-specific findings。

跨国共同变化因此可以表述为：

1. 物理墓地仍然重要；
2. Web 增加一个远程、异步、可反复访问的地址；
3. 原本由少数在场亲属完成的哀悼，可以扩展到分散的同学、朋友、网络社群；
4. 纪念开始同时具备“仪式”和“档案”两种属性；
5. 服务器寿命、隐私、账号与身份核验随之进入原本主要属于家庭和墓园的事务。

中国更具地方性的部分，是清明返乡、家庭孝道评价、墓园实体维护、超大规模人口迁移与中文商业纪念网站/微信生态叠在一起；这些不能简单等同于美国社交媒体 mourning。

## 10. 历史可见性：网络纪念看起来“保存得比墓前讲话更好”，但这种可见性非常偏

这一专题会产生一个特别强的 archive bias。

今天研究者容易看到：

- 公开网上纪念馆；
- 可索引的逝者姓名、生卒年；
- 公开纪念文章；
- guestbook 留言；
- 公开虚拟祭品记录；
- 平台公告与收费规则；
- 新闻报道中的截图和 URL。

研究者非常难看到：

- 墓前一家人的私下对话；
- 家庭微信群里的追思；
- 私信、QQ 消息、短信；
- 被密码锁住的网上纪念馆；
- 没有被 archive 抓到的图片、音乐和 Flash；
- 只存在于手机号/账号登录后的内容；
- 平台倒闭前用户是否完整导出；
- 家庭为什么认为某种方式“算数”或“不算数”。

因此必须固定：

> **historian-visible mourning != personally-important mourning**

甚至可能出现逆向选择：越私密、越痛苦、越家庭内部的内容，越不容易留下；越公开、模板化、面向搜索引擎的纪念页，越容易成为几十年后的“互联网丧亲史”。

## 11. 与重点矩阵的交叉

| 矩阵维度 | 本专题新增内容 |
|---|---|
| 教育 | 学生因学校日历无法返乡时，网上纪念提供 fallback |
| 就业 | 在外务工、长期海外生活、工作时间影响返乡祭扫 |
| 住房/迁移 | 家庭成员分散在不同城市/国家，墓地仍固定在原地点 |
| 婚姻家庭 | 对某种祭扫方式是否“尽孝/尽心”的判断仍由亲属关系共同生成 |
| 照护 | 死亡之后仍存在墓位维护和记忆照护劳动 |
| 非正规劳动 | 代客扫墓把网络订单转成现实身体劳动 |
| 长期中断 | 疫情使现场祭扫路线突然中断，远程通道承担连续性 |
| 证件与记录 | 网上纪念馆必须区分页面建立、死亡事实与身份核验 |
| 通信方式 | 书信/电话/网页/QQ/微信/视频共同参与死亡通知和追思 |
| 互联网平台 | 专门网墓、门户、网店、微信公众号、小程序等不断更替 |
| 信息获取 | URL 让远方亲友共享逝者资料；也可能产生错误/虚假死亡信息 |
| 社交关系 | 同学、朋友可绕过地理位置参与纪念 |
| 未来预期 | 2008 已有“网站会不会消失”的长期信任问题；2023+ 出现主动数字遗产安排 |
| 线上/线下身份 | 纪念馆中的 deceased identity 不等同于被核实的现实死亡身份 |
| 平台消失与记忆保存 | “永久纪念”对平台寿命、账号、域名和数据迁移提出长期要求 |

## 12. 证据等级与反例汇总

### 强证据

- 2001 同期媒体列出多家虚拟墓地 historical locators 与功能；
- 2002 同期记者进入 `CN.NETOR.COM` 并观察用户留言/祭奠功能；
- 2004 嘉定普通家庭实际建馆与亲友访问；
- 2004 重庆出现极低 adoption 的反例；
- 2008 林良英第一人称/同期采访：为外地亲友建妹妹纪念馆；
- 2008 中国青年报记录消费者对网页消失和长期付费服务的明确担忧；
- 2019 南京学生因不能返宁夏而建爷爷奶奶网上纪念堂；
- 2020 广州工作的河南人因为疫情第一次改走线上家庭追思；
- 2022 民政部网络/现场祭扫规模统计；
- 2023 年轻受访者关于死后数字痕迹保留/删除的不同选择；
- 2025 活人被错误建纪念馆的身份核验失败案例；
- 2026 民政部现场/网络祭扫 denominator。

### 重要反例

1. 2004 有站点、有完整功能，不代表普通家庭采用；
2. 2008 消费者已经担心网站本身先消失；
3. 2015 代客扫墓能被网上订购，不代表大多数异地家庭愿意接受；
4. 2019 大量现场祭扫与网上纪念并存；
5. 2022 网络祭扫高峰和现场受限同时发生，不能外推长期偏好；
6. 2025 页面可以在死亡事实未核实的情况下被创建；
7. 2026 现场祭扫重新远高于峰值日网络祭扫，说明 physical ritual 仍然非常强。

## 13. 后见之明风险

### 风险一：把 Internet 写成“祭祀现代化的必然替代”

错误。至少 2004、2008、2015、2019、2026 都有明确的 non-substitution evidence。

### 风险二：把“异地不能回来”写成“不在乎”

错误。很多在线/代祭案例恰恰是因为人高度在乎，才寻找替代路线。

### 风险三：用 2020—2022 疫情高峰倒推 2010s 的稳定偏好

错误。危机期间的 forced substitution 必须独立建模。

### 风险四：把“网上纪念馆”当成真实死亡证明

错误。2022/2025 相关案件已经直接证明 deceased identity 需要核验。

### 风险五：把平台自称“永久”当作技术事实

错误。永久是一种承诺、商业合同或愿望，不等于跨几十年的可验证数据保存。

### 风险六：把公开留言当作全部 grief

错误。公开 Web 在哀悼材料中有极强 selection bias。

## 14. 仍然不知道什么

1. 1990s 中国普通家庭如何实际组合电话、电报、书信和返乡来完成死亡通知，需要更多同期生活材料；
2. 2001—2005 各虚拟墓地的真实活跃用户分母和复访率；
3. Netor 早期付费馆与免费馆的数据保存合同、备份与迁移机制；
4. 早期纪念馆里图片、音乐、Flash 与留言是否分别存放在不同 host；
5. 用户忘记密码、建馆者死亡后谁能接管管理权；
6. 一家人内部对“网上祭扫算不算”的代际分歧有多普遍；
7. 海葬、树葬等无传统单体墓位路线，是否系统性提高对数字纪念地址的需求；
8. 各平台是否允许导出完整纪念数据，以及导出是否包含评论、祭品、时间戳和关系图；
9. 网络纪念平台关闭后，普通家庭实际有多少成功迁移过资料；
10. 社交媒体原生的死后账号与专业纪念网站之间，用户期望是否不同。

## 15. 这一轮改变了我们对“人怎么活着”的哪一点理解

死亡不是普通生活的一个黑点，之后什么都没有了。

对幸存者来说，它会新增长达几十年的生活任务：

```text
今年能不能回去
→ 墓碑谁来擦
→ 远方同学怎么参加
→ 孩子以后还能不能看到外婆年轻时的照片
→ 我想对父亲说的新消息放在哪里
→ 网站十年后还在不在
→ 我自己死后又希望别人留下什么
```

Internet 真正改变的，并不是“人可以不用扫墓了”。它先让一个已经离世的人拥有第二种地址：墓碑仍然在一个地方，但他的照片、故事、留言和亲友的后来生活可以在另一个地方持续累积。

这使普通家庭第一次能够把一部分哀悼从 **必须共同在场的空间事件**，拆成 **可以跨城市、跨年份反复进行的通信行为**。

但这种自由马上又带来新的维护劳动：页面要活着、域名要续、账号要有人接管、身份要核实、数据要能迁走，家庭还要决定哪些东西应该永远留下，哪些应该随本人一起消失。

过去需要维护的是墓；数字时代又多了一座需要维护的“地址”。

## 16. 本阶段饱和判断

本轮新增了：

- 一种此前未独立建模的生活路径：**死亡后长期继续关系与周期性祭扫**；
- 一个新的制度/平台接口：**deceased identity / memorial ownership / kin authorization**；
- 一个新的时代时间机制：**永久纪念愿望与平台寿命之间的冲突**；
- 一条 2008 同期第一人称证据；
- 一条 2019 同期学生迁移/日历冲突证据；
- 一个 2020—2022 现场路线中断后的远程仪式连续性机制；
- 一个 2023—2026 主动管理死后数字自我的新未来问题；
- 一个 1995 起的海外 online-cemetery 对照。

因此连续无实质新增计数保持 **0/3**，本阶段不进入 closure。
